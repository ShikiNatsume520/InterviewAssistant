### 前端实现

## 2. 快速原型结论

### 2.1 运行时模型上下文

原型：[frontend_phase3_runtime_model_context_probe.py](../prototypes/frontend_phase3_runtime_model_context_probe.py)

验证结果：

- `ContextVar` 能穿过 LangGraph 异步调度进入同步节点。
- 并发请求中的 API Key、Base URL 和模型配置互相隔离。
- 请求结束后上下文恢复为空。
- 敏感配置不进入 MemorySaver checkpoint。

### 2.2 停止边界

阶段 0 的取消探针已经验证：浏览器中止 POST SSE 后，异步生成器取消，图从最近完成的 checkpoint/超级步边界恢复。阶段 3 不重复创建相同探针。

本阶段“停止”定义为：

1. 用户点击当前输入框旁的停止按钮。
2. 前端调用当前请求的 `AbortController.abort()`。
3. 后端 SSE generator 收到取消，阶段 2 事件层追加 `task.interrupted`。
4. 未形成完整消息的 delta 从界面移除。
5. 再次进入或重试时从 checkpoint 恢复。

跨标签页停止、服务端任务管理端点和自动切换取消在阶段 9统一完善。

## 3. 前端工程建议

正式目录建议使用：

```text
frontend/
├─ src/
│  ├─ api/             HTTP、SSE 与错误协议
│  ├─ app/             路由与全局 Provider
│  ├─ components/      通用 UI
│  ├─ features/
│  │  ├─ identity/
│  │  ├─ threads/
│  │  ├─ timeline/
│  │  └─ model-config/
│  ├─ styles/          token 与全局样式
│  └─ main.tsx
├─ index.html
├─ package.json
├─ tsconfig.json
└─ vite.config.ts
```

建议依赖：

- `react`、`react-dom`。
- `react-router-dom`：路由和 Thread URL。
- `react-markdown` + `remark-gfm`：Markdown；禁用原始 HTML。
- `lucide-react`：代码原生图标。

第一版不引入 Zustand、Redux 和 TanStack Query。Thread 与事件 API 数量有限，使用 feature hooks + reducer 即可，避免同时存在多套缓存真相源。

CSS 使用普通 CSS + design tokens，不引入 Tailwind 或大型组件库。后续页面数量有限，定制布局和状态卡更容易保持一致。

本阶段没有 Resume 工作区，因此聊天区占据侧栏以外的全部空间。阶段 5 进入简历修改时才增加中间工作区，并把聊天区压到最右侧。

## 5. 时间线恢复

打开 `/threads/:threadId`：

1. 请求 Thread 元数据，404 时回到最近会话或欢迎页。
2. 无游标请求最新一页产品事件。
3. reducer 按 `eventId` 去重、按 `sequence` 排序。
4. 向上滚动用 `beforeEventId` 加载旧事件。
5. 当前 SSE 断线后用最后一个 durable `eventId` 调用 `afterEventId` 补齐。
6. transient delta 只保存在当前页面内存，收到终态消息后被替换；中断时丢弃。

前端不读取 `/v1/state` 拼接聊天历史，也不读取 LangGraph messages 展示旧内容。

## 6. 模型配置最小入口

游客要完成普通聊天，本阶段必须具备最小配置，但不提前建设阶段 8 的完整设置中心。

建议首次发送时若缺少配置，打开轻量弹层：

```text
Base URL
Model
API Key
[仅在当前浏览器标签页保存] [开始使用]
```

- 存入 `sessionStorage`，关闭标签页/浏览器会话后清除。
- API Key 不进入 React 全局可序列化状态、URL、Cookie或产品事件。
- 每次 `/v1/chat` 和 `/v1/checkpoint` 通过专用请求头提交。
- 开发人员身份隐藏表单，只显示使用服务端开发配置。
- 游客缺少配置时后端返回稳定错误，不回退 `.env`。

完整 Provider 预设、测试连接、记住设备和清除审计仍属于阶段 8。

## 7. 后端运行时模型配置

建议内部结构：

```text
RuntimeModelConfig
├─ api_key
├─ base_url
└─ model
```

FastAPI 根据服务端确认的 principal 选择来源：

```text
guest      → 必须读取本次请求头
developer  → 忽略游客请求头，使用 .env
Studio     → 不经过 FastAPI，继续使用 .env
```

请求头只在入口解析，随后设置到 `ContextVar`。`get_chat_model()` 每次实际调用读取当前上下文并构造模型，不缓存带凭据的实例。

以下模块中的模型单例需要移除：

- Main `chat_node`。
- Memory extraction。
- Resume Agent。
- Research Agent。
- 当前可能被对话链路触发的 Index Agent。

这会改变模型实例获取方式，但不修改图节点、边、State、Prompt 或业务路由。

## 8. 错误协议

HTTP 建议统一：

```json
{
  "error": {
    "code": "MODEL_CONFIG_REQUIRED",
    "message": "请先配置模型服务",
    "retryable": false
  }
}
```

SSE 已建立后出现错误时，通过持久化 `task.failed` 事件返回脱敏错误；不得返回请求头、Key、完整第三方响应或堆栈。

建议第一版错误码：

- `MODEL_CONFIG_REQUIRED`
- `MODEL_CONFIG_INVALID`
- `THREAD_NOT_FOUND`
- `TASK_CONFLICT`
- `UPSTREAM_UNAVAILABLE`
- `TASK_FAILED`

## 9. RAG 引用

普通回答正文与引用分开显示：

- `message.agent` 保存回答正文。
- 新增 `citation.list` 产品事件，以 `messageId` 关联回答。
- payload 只包含标题/文件名、行区间、摘要和允许展示的来源标识。
- 前端在消息下方显示“参考资料 N”，默认折叠。

不会从 Agent 消息文本中用正则猜测引用。

## 10. 部署边界

开发环境：

- Vite dev server 提供前端热更新。
- `/v1` 代理到 FastAPI。
- Cookie 与 SSE 保持同源体验，不开放宽泛 CORS。

生产环境建议：

- `npm run build` 生成 `frontend/dist/`。
- FastAPI 可挂载构建产物，或由同域反向代理分别服务静态资源和 `/v1`。
- React Router 未命中静态资源时回退 `index.html`。
- HTTPS 是游客提交 API Key 的硬要求。

旧 `static/index.html` 在阶段 3 验收后停止作为主页；`static/resume.html` 暂时保留到阶段 5 Resume 工作区验收。

## 11. 已确认结论

1. 正式 React 工程使用 `frontend/`。
2. 使用 React Router、react-markdown、remark-gfm、lucide-react；不引入状态库、Tailwind 和大型组件库。
3. 阶段 3 提供最小模型配置弹层，仅保存到 `sessionStorage`。
4. RAG Embedding 第一版继续作为服务端公共检索基础设施，使用服务端 SiliconFlow 配置。
5. 停止按钮使用 `AbortController`；跨页面/跨标签页服务端停止留到阶段 9。
6. React 构建产物接管 `/`；旧 `static/index.html` 仅在尚未构建 React 时作为过渡 fallback，`static/resume.html` 保留到阶段 5。

用户已确认上述方案，阶段 3 正式实现完成。
