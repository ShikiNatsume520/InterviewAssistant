# 前端重构阶段 5：Resume 工作区设计草案

> 当前状态：正式实现完成，等待阶段 4B + 阶段 5 联合验收。

## 1. 目标

在同一个会话页面内完成 Resume Agent 的计划确认、逐条修改审批、继续修改、保存为派生简历和放弃退出。聊天时间线不清空、不跳转；刷新或切换会话后，可以仅依靠持久产品事件恢复当前工作区和待决 Interrupt。

## 2. 对总体计划的架构修正

阶段 4 已将简历统一为用户级后端资源，因此阶段 5 不再：

- 从浏览器临时选择本地文件作为 Resume Agent输入；
- 把本地文件全文作为 Interrupt 回复提交；
- 由浏览器保存或覆盖源文件；
- 在工作区关闭时直接导出未入库草稿。

新的闭环是：Main Agent指定 `resume_id` → wrapper 读取只读源简历 → checkpoint 保存工作草稿 → 保存退出创建新派生简历 → 前端按 `output_resume_id` 下载。

## 3. 页面职责

### 3.1 左侧会话区

- 固定位置，不随聊天滚动；
- Resume 活动会话显示 Resume Agent 和待审批状态；
- 切换回来时恢复工作区与审批卡片。

### 3.2 中间 Resume 工作区

只在 `active_mode=resume` 时出现，并在 Resume Agent 整个会话生命周期内始终驻留；是否存在待审批 Interrupt 只影响 Diff 与审批状态，不影响工作区挂载。工作区仅承担：

- 当前 checkpoint 草稿的 Markdown/预览展示；
- 定位当前候选修改；
- 显示修改前和修改后的红绿 Diff；
- 显示当前序号、总数和所属章节；
- 文本选区，为“提出建议”或后续修改请求提供位置提示；
- 提示源简历只读、已批准修改不可逐条撤销。

工作区不展示计划按钮、审批按钮、普通工具状态、RAG 或深研进度。

### 3.2.1 LapisCV 渲染模式

本项目中的 `data/lapis-cv-vscode-v2.0.1` 不是独立 Markdown 方言或编译器，而是 LapisCV 2.0.1 的 VS Code 分发形式：

- `.vscode/settings.json` 将 `main.css + lapis-cv-serif.css` 注入 VS Code Markdown预览；
- Markdown主体仍是 CommonMark/GFM，但使用内嵌 HTML；
- `<div class="entry-title">` / `<div alt="entry-title">` 形成左右排列的经历标题；
- `<span class="icon">` 和标题里的私用区 Unicode实体依靠 `iconfont.ttf` 显示图标；
- `<img class="avatar">` / `<img alt="avatar">` 依靠 CSS 形成头像；
- 思源黑体、思源宋体、JetBrains Mono 和图标字体共同决定最终排版。

工作区精简为两个视图：

```text
源码 | 渲染对比
```

- `源码`：始终展示完整 Markdown；有待审批修改时，在全文原位置插入红色删除块和绿色新增块，而不是只展示两个局部片段；
- `渲染对比`：无 Diff 时直接渲染当前已批准草稿，不显示比较控件或颜色标记；有 Diff 时提供“修改前 / 修改后”切换。修改前渲染完整旧版本，并将本次被删除内容标为红色背景；修改后渲染完整候选版本，并将本次新增内容标为绿色背景。

无待审批 Diff 时默认打开 `渲染对比`，其效果等价于当前简历预览；存在 `resume_approve` 时默认打开全文源码 Diff，用户可切换到渲染对比查看前后版本。批准后进入下一状态，上一项红绿提示立即取消。

### 3.2.1.1 可调工作区宽度

左侧会话管理保持固定宽度。中间 Resume工作区与右侧聊天区之间增加鼠标拖动分隔线：

- 拖动时只改变中间与右侧占比；
- 工作区最小 480px、最大为可用宽度的 68%；
- 聊天区最小 380px；
- 双击分隔线恢复默认比例；
- 比例保存在浏览器 `localStorage`，刷新与切换会话后沿用同一设备偏好；
- 窗口缩小时重新执行边界限制，不允许任一区域被挤到不可用宽度。

### 3.2.2 安全渲染

当前 React使用 `react-markdown + remark-gfm`，默认不会渲染 Lapis模板中的原始 HTML。正式实现需要增加 `rehype-raw` 与 `rehype-sanitize`：

1. 解析内嵌 HTML；
2. 仅放行 Lapis实际需要的 `div/span/img/a` 等标签；
3. 仅放行 `class/alt/src/href` 等必要属性；
4. 禁止 `script`、`style`、iframe、事件属性和 `javascript:` URL；
5. 外部链接增加安全的 `rel`；
6. Lapis CSS 全部限制在 `.lapis-preview` 容器内，不允许污染聊天页面。

### 3.2.3 字体与性能

本地分发包含约 45 MB 的 TTF：思源黑体三种字重、思源宋体粗体、JetBrains Mono和图标字体。第一版按当前 `.vscode/settings.json` 的 Serif主题实现，并且：

- 字体只在用户第一次打开 Lapis预览时加载；
- 复用浏览器长期缓存；
- 不在聊天首屏加载；
- 正式发布时保留 LapisCV MIT声明，以及思源字体和 JetBrains Mono 对应的 OFL许可证文本；
- 后续可在不改变字体名称的前提下评估 WOFF2 压缩，第一版不做字体子集化，避免缺失用户简历中的汉字。

### 3.2.4 图片边界

模板支持远程 HTTPS 头像。当前 `my_resume.md` 使用 `./xjpic.jpg`，但该图片并不在现有 Lapis目录中，而且简历资源模型只保存 Markdown正文，因此浏览器无法可靠解析相对图片。

阶段 5 第一版：

- 支持 HTTPS 图片；
- 相对路径图片显示“图片资源未上传”占位，不猜测服务器文件路径；
- 不在本阶段增加简历附件上传；未来为 ResumeDocument 增加受 owner 隔离的 assets 后再支持相对图片。

### 3.3 右侧聊天区

- 保持 Main、Resume、用户消息的连续时间线；
- `plan_confirm` 显示计划确认卡片；
- `resume_approve` 显示当前修改说明与接受/拒绝/建议操作；
- `resume_hitl` 保持聊天框与发送按钮可用，用户的新消息作为 `new_request` 返回 `chat_node`；该状态额外显示“保存为新简历并退出”和“不保存并退出”，但退出不是必选操作；
- 非待命 Interrupt 不展示保存或退出按钮。

## 4. 产品事件与恢复

图执行仍只依赖 LangGraph state/checkpoint，不读取产品事件。服务端在检测到 Resume Interrupt 后，从 checkpoint 读取只用于展示的工作区快照，将其写入完整的 `interrupt.requested` 产品事件：

```text
interrupt.requested.payload
├─ phase
├─ workspace
│  ├─ resumeId
│  ├─ displayName
│  └─ draft
└─ phase-specific fields
```

前端按事件顺序寻找“最后一个 requested 且后面没有 resolved”的 Interrupt：

- 有 pending：恢复对应卡片和工作区；
- 已 resolved：历史卡片只读显示用户决定，不可重复提交；
- 新 Interrupt 到达：替换当前待决卡片和当前工作区快照。

审批提交后的图执行间隙没有 pending Interrupt，但工作区仍使用最近一次产品事件快照显示草稿；若本次决定为批准，则前端临时采用候选 `after` 作为当前展示版本，直到下一次完整工作区快照到达。只有保存或放弃退出、后端将 `active_mode` 切回 `chat` 后，工作区才关闭。

完整草稿只作为前端展示快照，绝不作为后端图输入。

## 5. Interrupt 契约

### 5.1 计划确认

```text
phase       plan_confirm
plan        string[]
workspace   当前工作区快照
actions     approve | suggest
```

### 5.2 逐条修改审批

```text
phase       resume_approve
editId      稳定 tool_call_id
ordinal     当前序号
total       当前批次总数
section     展示章节
reason      修改理由
beforeText  当前定位原文
afterText   候选替换文本
workspace   当前已批准草稿
actions     approve | reject | suggest
```

底层仍用 `grep_target + replace_content` 执行，但产品契约和 UI 不出现 grep 名称。

### 5.3 待命

```text
phase       resume_hitl
summary     本轮摘要
workspace   当前最终工作草稿
actions     new_request | save | discard
```

只有该阶段允许保存或放弃退出。

## 6. 防重复提交

- 提交审批时前端立即禁用按钮；
- 服务端只能恢复当前 checkpoint 中真实 pending Interrupt；
- `interrupt.resolved` 写入产品时间线后，该历史卡片永久只读；
- 保存节点继续使用阶段 4B 的 `resume_session_id` 幂等创建派生简历。

## 6.1 预期 Interrupt 与异常中断

LangGraph图中的 `interrupt()` 是正常的人机交互状态，不属于执行故障：

- 正常到达 Interrupt 时，Thread状态记为 `waiting`，侧栏显示“待确认”；
- 前端直接展示对应审批卡片，不显示“上次执行已中断”提示；
- 用户点击审批或提交结构化回复后，使用 `Command(resume=...)` 恢复；不需要额外点击“从最近检查点继续”；
- 只有浏览器断线、用户主动停止、服务进程异常退出或节点执行失败等非预期暂停，才使用 `interrupted` 并提供“从最近检查点继续”。

因此 Thread状态扩展为：

```text
idle | running | waiting | interrupted
```

## 7. 本阶段后端改动

- `grep_replace` 工具参数补充只用于展示的 `section` 与 `reason`；执行仍只依赖 target/replace；
- `ResumeApprovePayload` 增加稳定 edit ID、序号、章节、理由和局部前后文本；
- 服务端在持久化 Resume Interrupt 产品事件时附加只读 workspace snapshot；
- `interrupt.resolved` 记录规范化后的用户 action；
- 退役旧 `/resume` 页面入口及旧 `resume_select` 正常路径依赖；
- 不改变计划、逐条审批、待命、保存和放弃的图路由。

Lapis渲染全部在浏览器完成，后端不把 Markdown 转换为 HTML，也不执行用户 HTML。

## 8. 本阶段前端改动

- 三栏条件布局；Resume 未激活时恢复“左侧会话 + 右侧宽聊天”；
- 新增 ResumeWorkspace；
- 新增 PlanConfirmCard、ResumeApproveCard、ResumeStandbyCard；
- `streamGraph` 支持发送结构化 `resume_value`；
- 从产品事件恢复 pending Interrupt、工作草稿和已决审批历史；
- 保存成功后刷新简历列表，并提供新派生简历下载入口。

## 9. 不进入本阶段

- 不重写 `grep_replace` 编辑机制；
- 不实现已批准修改的撤销；
- 不允许用户直接编辑 Markdown 草稿；
- 不实现移动端；
- 不实现 Research 任务卡与知识库确认。
- 不实现服务端 PDF 导出和浏览器打印排版承诺；本阶段只提供屏幕预览。
- 不实现简历图片附件库。

## 10. 待确认

1. 工作区 Markdown 与预览是否均为只读。草案推荐只读，所有修改仍经过 Resume Agent审批。
2. 中间工作区和右侧聊天区是否需要可拖动分隔线。草案推荐第一版固定比例，避免把布局状态持久化引入本阶段。
3. 当前实现中，拒绝一条修改会终止当前批次剩余候选并进入待命；不是自动审批下一条。草案建议阶段 5 保持现有图语义，不顺带重写执行循环。
4. 历史已决审批卡片是否完整保留。草案推荐保留摘要、序号和决定，折叠前后文本，且不可再次操作。
