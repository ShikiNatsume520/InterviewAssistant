# 前端重构阶段 0 验证记录

> 状态：关键风险探针完成，等待用户验收
>
> 本阶段只修改 `prototypes/` 与文档，没有修改正式后端、测试或前端工程。

## 1. 验证范围

阶段 0 验证以下五项风险：

1. SSE 执行取消与 checkpoint 恢复边界。
2. 嵌套子图消息的 Agent 来源映射。
3. 运行时 API Key 贯穿父/子图且不进入 checkpoint。
4. 游客知识库的 Chroma 隔离方式。
5. React 对 POST SSE、事件去重和恢复的状态模型。

## 2. 探针 1：取消与 checkpoint 恢复

原型：[frontend_phase0_cancel_checkpoint_probe.py](../prototypes/frontend_phase0_cancel_checkpoint_probe.py)

### 验证结果

- 取消正在消费的 `graph.astream()` 会传播 `CancelledError`。
- 最近 checkpoint 保持在未完成节点或超级步之前。
- `graph.astream(None, config)` 会从最近 checkpoint 继续，并重新执行未完成节点。
- 节点在返回 state update 前产生的外部副作用，会在恢复重跑时再次发生。

### 已确认产品语义

- 恢复边界采用 LangGraph checkpoint/超级步，而不是节点内部断点。
- 未完成的单个节点允许整体重跑。
- 同一未完成超级步中的多个节点允许整体重跑。
- 搜索、抓取等重复执行可以接受。
- 文件写入、索引和删除等操作需保证重跑后的最终结果一致。

### 结论

机制可用于本项目的自动中断与恢复需求。正式实现不能向用户承诺从节点内部精确续跑。

## 3. 探针 2：嵌套子图 namespace

原型：[frontend_phase0_subgraph_namespace_probe.py](../prototypes/frontend_phase0_subgraph_namespace_probe.py)

### 实际输出

```text
namespace=('resume_agent:<uuid>',)   content='resume-child-token'
namespace=()                         content='resume-wrapper-done'
namespace=('research_agent:<uuid>',) content='research-child-token'
namespace=()                         content='research-wrapper-done'
```

### 结论

- 当前模块级预编译子图 + 静态 wrapper 模式可以保留。
- `subgraphs=True` 时，子图事件 namespace 首段稳定包含父 wrapper 节点名。
- `resume_agent:<id>` 可映射为 Resume Agent。
- `research_agent:<id>` 可映射为 Research Agent。
- 空 namespace 可映射为 Main Agent。
- UUID 部分是运行实例 ID，不能作为稳定 Agent 身份；只解析冒号前的节点名。

## 4. 探针 3：运行时 API Key

原型：[frontend_phase0_runtime_secret_probe.py](../prototypes/frontend_phase0_runtime_secret_probe.py)

探针使用假的 Key 标记，不调用网络模型。

### 验证结果

- 父图节点可以从 `RunnableConfig.configurable` 读取运行时模型配置。
- 静态 wrapper 调用的子图继承相同配置。
- 节点只把非敏感结果写入 state 时，MemorySaver 的 snapshot 与 checkpoint 记录中没有 Key 标记。

### 结论

- 游客运行时凭据通过 `RunnableConfig` 贯穿父/子图在机制上可行。
- Key 不得写入任何 state、message、event、metadata 或日志。
- 当前正式代码的模块级 LLM 缓存仍需重构；该探针只证明目标机制，不代表现有实现已经安全。
- 正式阶段还需用 SQLite checkpointer 再做一次不落盘验证，并检查异常追踪与第三方日志。

## 5. 探针 4：Chroma 游客隔离

原型：[frontend_phase0_kb_isolation_probe.py](../prototypes/frontend_phase0_kb_isolation_probe.py)

探针使用临时 Chroma 目录和显式二维 embedding，不调用在线 embedding 服务。

### 共享 collection

验证通过：

- 游客 ID 加入 chunk ID 后，同名文件不会互相覆盖。
- 强制 `owner_id` filter 后，查询只返回当前游客资料。
- `$or` filter 可以联合查询公共资料和当前游客资料。
- 按 `owner_id` 删除不会删除其他游客或公共资料。

风险：任何一次查询或删除遗漏 owner filter，都可能造成越权。

### 每游客独立 collection

验证通过：

- 不同游客可以使用相同文件名和 chunk ID。
- 查询和删除天然限定在当前 collection。
- 删除一个游客数据不会影响其他游客或公共 collection。

代价：公共库与个人库需要分别检索后合并结果；collection 生命周期和数量需要管理。

### Windows 临时目录现象

Chroma `PersistentClient` 在 Python 进程存活时持有底层文件句柄，`TemporaryDirectory` 无法立即删除 `data_level0.bin`。进程退出后，该探针目录可以正常删除。

这不是数据隔离失败，但意味着运行期间不能依赖“删除整个 Chroma 物理目录”作为普通业务操作。删除文档或 collection 应通过 Chroma API 完成。

### 建议

首版优先采用：

```text
公共知识库 collection
+ 每游客独立个人 collection
```

理由是越权风险更低，更符合未来 Skill 和用户资源的隔离边界。公共与个人检索结果的合并策略在阶段 7 原型中进一步确定。

该建议需要用户批准后才成为正式设计决策。

## 6. 探针 5：React POST SSE 状态模型

原型目录：[frontend-phase0-sse](../prototypes/frontend-phase0-sse/)

用户安装的隔离依赖：

- React 19.2.7
- React DOM 19.2.7
- Vite 8.1.4
- TypeScript 7.0.2

### 验证内容

- React + TypeScript + Vite production build。
- 浏览器 `fetch(POST) + ReadableStream` SSE 消费。
- 跨任意网络 chunk 的 SSE 分帧。
- `id/event/data` 字段解析。
- 稳定事件 ID 去重。
- 状态序列化和恢复。
- 请求携带 `afterEventId`，从最后事件之后续传。

### 自动验证结果

```text
PASS: 分块 POST SSE 被正确解析
PASS: 重复 evt-3 只保留一次
PASS: 序列化恢复后从 evt-5 续传，没有重复事件
```

### 结论

- POST SSE 满足当前交互需求，不需要改用 GET `EventSource`。
- 后端事件必须提供稳定、单调有序的事件 ID。
- 前端 reducer 必须按 ID 幂等处理，不能假设网络只发送一次。
- 恢复接口应接受 `afterEventId` 或等价游标。
- React 刷新恢复不能只依赖浏览器状态；正式产品仍以服务端产品事件为事实来源，浏览器存储只用于快速显示或临时状态。

## 7. 阶段 0 总结

五项关键机制均可行，没有发现必须放弃当前总体架构的阻断问题。

阶段 1 开始前需要用户确认两项设计判断：

1. 是否批准“公共 collection + 每游客独立个人 collection”作为知识库隔离方向？
2. 是否批准产品事件采用稳定事件 ID，并支持 `afterEventId` 游标恢复？

阶段 0 验收前不进入阶段 1，不修改正式代码，也不创建阶段 1 模块或占位文件。
