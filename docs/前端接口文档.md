# InterviewAssistant 前后端接口文档

> 用途：供 React（或其他框架）重构前端时，按本文档**兼容现有后端**的方式开发。
> 后端实现：[src/server/app.py](../src/server/app.py)；中断契约：[src/kernel/contracts.py](../src/kernel/contracts.py)。
> 现有前端（参考实现）：[static/index.html](../static/index.html)（主页）、[static/resume.html](../static/resume.html)（简历优化页）。

---

## 1. 总览

### 1.1 架构范式

- **后端驱动 + checkpoint 恢复**：后端持有编译后的 LangGraph 主图单例 + `AsyncSqliteSaver`（SQLite checkpoint）。前端不发业务逻辑，只发「用户消息 / interrupt resume 值 / 续跑信号」，由后端跑图、流式回推 token。
- **单会话**：当前 `GET /v1/thread` 是进程内存单会话实现（重启丢失），多会话为后续扩展点。
- **两个前端页面**：
  - 主页 `/`：通用对话 + 知识问答 + 深研大纲确认 + 连通性提示 + 计划确认。
  - 简历页 `/resume`：简历优化专用（左栏简历内容 / 右栏对话），由主页检测到 `in_resume` 后跳转。

### 1.2 前端职责边界

前端需要实现的状态机：

1. **init**：`GET /v1/thread` 拿 `thread_id` → `GET /v1/state` 解析 checkpoint 快照 → 按 `in_resume` / `pending_interrupt` / `next` 路由。
2. **发送消息**：`POST /v1/chat`（SSE），消费 `token` / `interrupt` / `done` 三类事件。
3. **续跑**：卡在节点间（`next` 非空且无 interrupt）时 `POST /v1/checkpoint`（SSE）从最近 checkpoint 续跑。
4. **interrupt 应答**：根据 `pending_interrupt.phase` 渲染对应 UI，用户操作后把 resume 值经 `POST /v1/chat` 的 `resume_value` 回传。

### 1.3 启动方式

```bash
uv run langgraph dev          # LangGraph Studio 调试
# 或
python -m uvicorn server.app:app --host 0.0.0.0 --port 8000 --reload
```

默认后端在 `http://localhost:8000`。当前前端静态文件直接挂载在同源 `/` 与 `/static`。

## 2. 通用约定

### 2.1 Base URL & 跨域

- 现有前端与后端**同源**（FastAPI 挂载静态文件），故无 CORS 配置。
- **React 重构注意**：若用 Vite dev server（默认 `localhost:5173`）独立部署前端，需在后端 [src/server/app.py](../src/server/app.py) 增加 `CORSMiddleware`，否则浏览器会拦截跨域请求 + SSE。SSE 跨域还需确认 `EventSourceResponse` 的响应头允许目标 Origin。
- 生产环境推荐反向代理（nginx）把 `/v1/*` 转发到后端，前端同源访问，避免 CORS。

### 2.2 会话标识

- `thread_id`：会话线程标识，贯穿所有端点，用于 checkpoint 回放。前端从 `GET /v1/thread` 获取，存于内存 / URL。
- `user_id`：用户标识（长期记忆 Store 键控），默认 `"default"`，前端可填（主页有输入框，默认 `test_user`）。

### 2.3 SSE 帧格式

后端用 `sse-starlette`，帧以 CRLF `\r\n\r\n` 分隔。每帧：

```
event: <事件名>
data: <JSON 字符串>
```

前端解析时按 `\r?\n` 切行，`event:` 取事件名，多个 `data:` 行用 `\n` 拼接。参考 [static/index.html](../static/index.html) 的 `parseSSE()`。

> React 中可用 `fetch` + `ReadableStream` 手动解析（现有前端即此方案），或用 `@microsoft/fetch-event-source` 等库。原生 `EventSource` 仅支持 GET，**不能**用于 `POST /v1/chat`。

### 2.4 内容类型

- 请求：`Content-Type: application/json`（`/v1/chat`、`/v1/checkpoint`）。
- 响应：SSE 流（`text/event-stream`）或 JSON（`/v1/state`、`/v1/thread`、`/health`）。

## 3. 端点详解

### 3.1 `GET /v1/thread` — 获取会话 thread_id

主页 init 第一步。

**请求**：无参数。

**响应** `200`：
```json
{ "thread_id": "web-a1b2c3d4e5f6" }
```

**说明**：单会话实现，进程内存生成 `web-` + 12 位 hex；首次访问自动生成，后续返回同一个。重启丢失。

---

### 3.2 `GET /v1/state?thread_id=<tid>` — 解析 checkpoint 快照

前端 init 第二步，返回路由 + 渲染所需的全部数据。

**请求**：query 参数 `thread_id`（必填）。

**响应** `200`：
```jsonc
{
  "thread_id": "web-...",
  "next": ["chat_node"],              // 主图待执行节点列表，空数组=已 END / 无 checkpoint
  "pending_interrupt": { ... } | null, // 当前挂起的 interrupt payload（已 schema 校验），无则 null
  "in_resume": true,                  // 是否在 resume 子图（next 含 resume_agent 或子图 state 存在）
  "main": {
    "messages": [ { "type": "human", "content": "..." }, { "type": "ai", "content": "..." } ],
    "current_resume": "",             // 主图 state.current_resume（resume 子图退出时回填）
    "citations": [ { "file_path": "...", "start_line": 1, "end_line": 10, "content": "...", "score": 0.87 } ]
  },
  "resume": {                         // resume 子图 state 摘要，非 resume 会话为 null
    "intent": "突出项目经历，精简技能",
    "resume_shot": "# 张三\n...",
    "resume_file": "my_resume.md",
    "messages": [ ... ],
    "last_summary": "",
    "plan": ["步骤1", "步骤2"]
  } | null
}
```

**前端路由逻辑**（参考 [static/index.html](../static/index.html) `initFromState`）：

| 条件 | 动作 |
|------|------|
| `in_resume === true` | 跳转 `/resume?thread=<tid>`（resume 页再自行 init） |
| `pending_interrupt` 非空 | 就地渲染 interrupt UI（见第 5 节） |
| `next` 非空且无 interrupt | 卡在节点间 → `POST /v1/checkpoint` 续跑 |
| `next` 为空 | 已 END / 无 checkpoint → 渲染历史 messages，就绪 |

---

### 3.3 `POST /v1/chat` — 流式对话（SSE）

前端发送按钮 / interrupt 应答 / resume 页所有交互都走此端点。

**请求体** `ChatRequest`：
```jsonc
{
  "user_id": "test_user",          // 可选，默认 "default"
  "thread_id": "web-...",          // 必填
  "message": "用户消息内容",        // 可选，恢复 interrupt / 续跑时可空字符串
  "resume_value": <任意> | null     // 可选，恢复 interrupt 时传给子图的值；提供则优先于 message
}
```

`resume_value` 形态见第 5 节（每种 interrupt 对应一种）。

**后端行为**：
- 检测当前 thread 是否有 pending interrupt：
  - **有** → `Command(resume=resume_value ?? message)` 恢复（不在开头重复推 interrupt，前端上一流末已收到）。
  - **无** → 新 `HumanMessage(message)` 启动一轮。
- `astream(stream_mode="messages", subgraphs=True)` 捕获主图 + 嵌套子图 token，按 namespace 归一化后推 `token` 事件。
- 流结束后查 interrupt：有 → 推 `interrupt`；无 → 推 `done`。

**响应**：SSE 流，事件见第 4 节。

---

### 3.4 `POST /v1/checkpoint` — 从最近 checkpoint 续跑（SSE）

前端 init 末尾，当 `next` 非空且无 interrupt 时调用，刷新恢复 / 卡节点间自动续跑。

**请求体** `CheckpointRequest`：
```jsonc
{
  "thread_id": "web-...",   // 必填
  "user_id": "default"      // 可选
}
```

**后端行为**：
- 查 state：
  - `next` 为空 → 已 END / 无 checkpoint：直接推当前 `interrupt` 或空 `done`。
  - `next` 非空 → `astream(None, config)` 让 LangGraph 自动加载最近 checkpoint 继续下一超级步。
- 复用 `/v1/chat` 的 `_stream_graph`，事件同第 4 节。

**响应**：SSE 流，事件见第 4 节。

---

### 3.5 `GET /health` — 健康检查

```json
{ "status": "ok" }   // 或 "warming"（图未编译完成时）
```

---

### 3.6 静态资源 & 页面

| 路径 | 说明 |
|------|------|
| `GET /` | 返回主页 HTML（`static/index.html`） |
| `GET /resume` | 返回简历页 HTML（`static/resume.html`） |

## 4. SSE 事件详解

`/v1/chat` 与 `/v1/checkpoint` 共用以下三类事件。

### 4.1 `event: token` — LLM 流式 token

```jsonc
{ "ns": "main", "text": "你好" }
```

| 字段 | 说明 |
|------|------|
| `ns` | 来源标签：`"main"`（主图）或 `"resume_agent"`（简历子图）。其他子图取 namespace 首元素原样 |
| `text` | 本帧 token 文本 |

**前端处理**：
- 主页：`ns === "main"` 的 token 追加到当前 AI 气泡。
- resume 页：`ns === "resume_agent"` 的 token 追加到右栏当前 AI 消息。
- 不同 `ns` 的 token 应分流到对应消息流（现有两页各只关心一种 ns）。

### 4.2 `event: interrupt` — 图挂起，等待用户确认

```jsonc
{ "interrupts": [ { "phase": "plan_confirm", "plan": ["..."] } ] }
```

- `data.interrupts` 是数组，前端取 `[0]` 作为当前 interrupt payload。
- payload 形状由 `phase` 决定，见第 5 节。
- 收到此事件后，前端渲染对应 interrupt UI，并把 resume 值经下一次 `POST /v1/chat` 的 `resume_value` 回传。

> 注意：后端在 `/v1/chat` 恢复 interrupt 时**不会**在流开头重复推该 interrupt（前端上一流末已收到）。新的 interrupt 只会在恢复后跑到下一个挂起点时由流末推。

### 4.3 `event: done` — 本轮结束且无 interrupt

```jsonc
{
  "last_message": "本轮 AI 最后一条消息的前 500 字",
  "current_resume": "# 优化后的简历全文...",
  "citations": [ { "file_path": "...", "start_line": 1, "end_line": 10, "content": "...", "score": 0.87 } ]
}
```

| 字段 | 说明 |
|------|------|
| `last_message` | 主图 state 最后一条 AI 消息内容（截断 500 字） |
| `current_resume` | 主图 state.current_resume（resume 子图退出时回填的最终简历草稿） |
| `citations` | 本轮检索引用列表（见第 6.1 节） |

**前端处理**：
- 主页：`citations` 非空 → 渲染引用来源。
- resume 页：`current_resume` 非空 → 触发简历下载（`resume_edited.md`），延迟返回主页 `/`。

## 5. Interrupt 契约（核心）

所有 interrupt payload 含 `phase` 字段标识类型。payload 由 [src/kernel/contracts.py](../src/kernel/contracts.py) 的 Pydantic schema 校验后序列化。

### 5.1 payload 形状（后端 → 前端）

#### `plan_confirm` — 简历优化计划确认（resume 子图）

```jsonc
{ "phase": "plan_confirm", "plan": ["步骤1：精简技能", "步骤2：突出项目"] }
```

#### `resume_select` — 选择简历文件（resume 子图入口）

```jsonc
{ "phase": "resume_select", "intent": "突出项目经历，精简技能" }
```

后端不扫不读文件，仅挂起等前端回传 `{resume_file, resume_shot}`。`intent` 是主图精炼的修改 query，主页跳 `/resume` 时走 URL 传给 resume 页作右栏首条消息。

#### `resume_approve` — 单波修改审批（resume 子图）

```jsonc
{
  "phase": "resume_approve",
  "before": "修改前的简历全文",
  "after": "修改后的简历全文",
  "edits": [
    { "grep_target": "要定位并替换的原文片段（标红）", "replace_content": "替换的新内容（标绿）" }
  ]
}
```

前端用 `edits` 在 `before` 文本上做 diff 高亮（`grep_target` 标红删除线、`replace_content` 标绿）。approve → 本地 shot 取 `after`；reject/suggest → 取 `before`（撤销整波）。

#### `resume_hitl` — 常驻会话待命（resume 子图）

```jsonc
{ "phase": "resume_hitl", "summary": "本次会话的修改总结" }
```

用户可选「继续修改」（发新意图）或「退出」（保存 / 不保存）。

#### `outline_confirm` — 深研大纲确认（research 子图）

```jsonc
{ "phase": "outline_confirm", "gap_topic": "知识缺口主题", "outline": ["检索词1", "检索词2"] }
```

#### `connectivity_check` — 连通性失败提示（research 子图）

```jsonc
{ "phase": "connectivity_check", "attempts": 2, "msg": "无法连接搜索服务，请挂梯子后继续" }
```

3 次失败后后端自动 abort。

### 5.2 resume 值形状（前端 → 后端）

通过 `POST /v1/chat` 的 `resume_value` 字段回传。

**统一规范（推荐，新前端按此开发）**：所有 resume 值统一为 `{action: <枚举>, ...附带字段}` dict。后端在 `Command(resume=...)` 前有归一化层，会把旧前端裸串/旧 dict 自动转成规范 dict，**旧前端与新前端都能跑**。

| 触发 phase | 规范 resume_value | 说明 |
|-----------|-------------------|------|
| `resume_select` | `{ "action": "select", "resume_file": "my_resume.md", "resume_shot": "简历全文" }` | 前端选简历文件后回传 |
| `resume_approve`（批准） | `{ "action": "approve" }` | |
| `resume_approve`（拒绝） | `{ "action": "reject" }` | |
| `resume_approve`（建议） | `{ "action": "suggest", "suggestion": "...", "selection": "" }` | `selection` 可选 |
| `plan_confirm`（批准） | `{ "action": "approve" }` | 计划无 reject |
| `plan_confirm`（建议） | `{ "action": "suggest", "suggestion": "...", "selection": "" }` | |
| `outline_confirm`（批准） | `{ "action": "approve" }` | |
| `outline_confirm`（拒绝） | `{ "action": "reject" }` | |
| `outline_confirm`（建议） | `{ "action": "suggest", "suggestion": "..." }` | |
| `resume_hitl`（继续修改） | `{ "action": "new_request", "request": "新意图", "selection": "" }` | `selection` 可选 |
| `resume_hitl`（退出） | `{ "action": "exit", "save": true }` | `save=true` 保存退出，`false` 放弃 |
| `connectivity_check`（继续） | `{ "action": "continue" }` | |

**归一化层兼容的旧形态**（旧前端继续可用，新前端不必关心）：

| 旧形态 | 归一化为 |
|--------|---------|
| `"approve"` / `"reject"` / `"continue"`（裸串） | `{action:"approve"}` / `{action:"reject"}` / `{action:"continue"}` |
| `"拒绝"` / `"拒绝深研"`（outline_confirm 旧中文） | `{action:"reject"}` |
| `{decision:"approve"}` / `{decision:"suggest", suggestion}` | `{action:"approve"}` / `{action:"suggest", suggestion, selection}` |
| `{resume_file, resume_shot}`（无 action） | `{action:"select", resume_file, resume_shot}` |
| `{action:"new_request", request}` / `{action:"exit", save}`（hitl 已规范） | 原样透传 |

> 归一化 + schema 校验逻辑在 [src/kernel/contracts.py](../src/kernel/contracts.py) 的 `normalize_resume_value` + `PHASE_TO_INBOUND`，server 调用在 [src/server/app.py](../src/server/app.py) 的 `_normalize_and_validate`。子图节点只读规范字段（`action` / `suggestion` / `selection` / `request` / `save` / `resume_file` / `resume_shot`），不再做裸串兜底。

## 6. 数据结构

### 6.1 `Citation` — 检索引用

```jsonc
{
  "file_path": "langgraph_state.md",   // 文件名（不含目录）
  "start_line": 1,                      // 起始行号（1-based）
  "end_line": 42,                       // 结束行号（1-based）
  "content": "命中区间内容",
  "score": 0.87                         // 归一化置信度 (0, 1]
}
```

> **行级引用是硬约束**：切片 metadata 必须保留 `start_line` / `end_line`，前端渲染引用时必须显示文件名 + 行区间。

### 6.2 序列化后的 `message`

`/v1/state` 的 `main.messages` / `resume.messages` 中每条：

```jsonc
{
  "type": "human" | "ai" | "system" | "tool",
  "content": "消息文本",
  "tool_calls": [ { "name": "grep_replace", "args": { ... } } ]  // 仅 AI 带 tool_calls 时存在
}
```

### 6.3 `edits` 项（resume_approve）

```jsonc
{ "grep_target": "原文片段", "replace_content": "新内容" }
```

### 6.4 主图 state 关键字段（`/v1/state.main`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `messages` | `message[]` | 对话历史 |
| `current_resume` | `string` | resume 子图退出时回填的最终简历 |
| `citations` | `Citation[]` | 最后检索的结构化引用 |

### 6.5 resume 子图 state 摘要（`/v1/state.resume`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `intent` | `string` | 主图精炼的修改 query |
| `resume_shot` | `string` | 当前简历全文 |
| `resume_file` | `string` | 选定的简历文件名 |
| `messages` | `message[]` | 子图对话历史 |
| `last_summary` | `string` | chat_node 总结 |
| `plan` | `string[]` | 修改计划步骤 |

## 7. 页面流转

### 7.1 主页 `/`

```
initThread() → GET /v1/thread
    ↓
initFromState(tid) → GET /v1/state?thread_id=tid
    ├── in_resume=true → 跳转 /resume?thread=<tid>
    ├── pending_interrupt → 渲染 interrupt UI
    ├── next 非空 → POST /v1/checkpoint 续跑
    └── next 空 → 渲染历史，就绪
```

收到 `resume_select` interrupt → 跳转 `/resume?thread=<tid>&intent=<intent>`。

### 7.2 简历页 `/resume`

```
init() → GET /v1/state?thread_id=<tid>（tid 来自 URL ?thread=）
    ├── !in_resume → 跳回 /
    ├── resume.resume_shot → 渲染左栏
    ├── resume.messages → 渲染右栏
    ├── pending_interrupt → renderInterruptUI
    ├── next 非空 → POST /v1/checkpoint 续跑
    └── next 空 → 会话已结束
```

收到 `done` 且 `current_resume` 非空 → 下载 `resume_edited.md` → 延迟 800ms 跳回 `/`。

### 7.3 两页共享的 SSE 消费流程

```
fetch POST → ReadableStream
  循环读帧:
    token(ns=main|resume_agent) → 追加当前 AI 消息
    interrupt → 暂存 localInterrupt，流末渲染
    done → 渲染 citations / 触发下载
  流结束 → 渲染 localInterrupt（若有）
```

## 8. React 重构兼容性注意事项

1. **CORS**：独立 dev server 部署需后端加 `CORSMiddleware`（当前无配置）。见 2.1。

2. **resume 值已统一**：所有 inbound resume 值现已统一为 `{action, ...}` dict（见 5.2）。后端有归一化层兼容旧前端裸串/旧 dict，**新 React 前端直接发规范 dict 即可，旧 static/ 前端无需改动继续可用**。子图节点只读规范字段，不再做裸串兜底。

3. **SSE 解析**：`/v1/chat` 是 POST，不能用原生 `EventSource`（仅 GET）。用 `fetch` + `ReadableStream` 手解析，或 `@microsoft/fetch-event-source`。帧以 `\r\n\r\n` 分隔。

4. **interrupt 不重复推送**：`/v1/chat` 恢复 interrupt 时流开头不重推该 interrupt。前端状态机须记住「上一流末收到的 interrupt」，恢复后只等下一个挂起点的新 interrupt，不要在恢复请求开头期待重复。

5. **刷新恢复**：页面刷新后经 `GET /v1/state` 重建状态，`next` 非空时 `POST /v1/checkpoint` 续跑。LLM 节点同步 invoke 不可中断，保证其完成存档——前端断开 SSE 不会丢失已完成的节点。

6. **单会话限制**：`GET /v1/thread` 进程内存单会话，重启丢失。若 React 版要支持多会话 / 历史列表，需后端扩展（当前未实现）。

7. **`done.last_message` 截断 500 字**：完整内容以 `/v1/state.main.messages` 最后一条 AI 消息为准。流式 token 已实时推送完整内容，`done` 的 `last_message` 仅作兜底摘要。

8. **`resume_select` 文件读取在前端**：后端不扫文件，前端用 `<input type="file" accept=".md">` 读取本地 `.md` 文件内容，整篇作为 `resume_shot` 回传。现有 resume 页用 `webkitdirectory` 扫目录的代码是历史遗留，当前实际是单文件选择（`readAndSelect`）。

9. **token namespace 分流**：`ns` 可能是 `"main"` / `"resume_agent"` / 其他子图首元素。重构时应设计按 `ns` 路由到不同消息流的能力，便于未来扩展子图。

10. **静态页面端点可移除**：`GET /` 与 `GET /resume` 仅返回测试用 HTML，React 接管路由后后端可只保留 `/v1/*` + `/health`。
