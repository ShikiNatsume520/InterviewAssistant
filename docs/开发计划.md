## 一、协作闭环（每阶段固定，不跳步）

1. **边界陈述**：文字说明本阶段目标、实现范围、不做什么、接口契约、验收方式。
2. **快速原型**：在 `prototypes/phaseN_xxx.py` 放可运行最小原型，验证关键技术风险。
3. **协商**：用户对边界/原型提意见，迭代至双方无异议。
4. **正式实现**：在 `src/`（及 `tests/`）实现，满足 ruff + mypy `--strict` + 测试。
5. **验收**：用户按阶段验收方式（Studio 轨迹 / pytest / 脚本）确认通过。
6. **git 存档**：验收通过后，在用户指引下提交 / 打 tag。未验收不存档。

## 二、前置决策（已与用户拍板 ✅）

1. **LLM provider**：OpenAI 兼容端点（`langchain-openai` `ChatOpenAI`，`base_url`/`model`/`api_key` 走 `.env`）。可对接 OpenAI / DeepSeek / Qwen / 智谱等。所有 `chat_node`、Memory、Deep Research 统一用此。
2. **Embedding**：本地 `sentence-transformers`（中文优先 `bge-small-zh` / `bge-m3` 一类），离线推理、无 API 费用。Chroma `embedding_function` 指向它。
3. **Grep 策略（设计文档 7.1）**：混合 —— 默认「向量命中文件后定向 grep」，向量得分全部偏低时兜底触发「全目录全量 grep」召回。
4. **简历优化架构（设计文档 7.2，重要调整）**：简历优化逻辑**独立为子图 `resume_agent`**，复杂逻辑下沉子图，主图只做路由激活。草稿暂存 / 回退状态持久化到 Store（按 `user_id` 存版本栈）；主图 router 识别"优化简历"意图后激活子 agent，前端进入草稿维护态。`MainState` 预留 `resume_subgraph_input` / `resume_subgraph_output` 槽位。
5. **git 初始化**：仓库当前非 git 仓库，Phase 0 完成 `git init` + 首次提交（待用户在计划审阅时最终确认）。

## 三、阶段划分

> 顺序调整说明：设计文档第 6 节原图为「Phase3 记忆与简历 → Phase4 SQLite → Phase5 FastAPI → 后续深研」。
> 本草稿建议调整为 **SQLite 断点 + 记忆（Phase 4）先行，简历优化并入 FastAPI 端到端（Phase 5），深研收尾（Phase 6）**。
> 理由：① `SqliteSaver` 是 Memory `Store` 的持久化基础，先搭持久化再做记忆更顺；② 简历优化需要端到端接口才能真实多轮交互；③ 深研依赖 RAG 的 `gap_topic` 与 Index Agent，放最后。
> **如你更倾向设计文档原顺序，请在审阅时指出，我可回调。**

### Phase 0 — 项目骨架与前置
- **目标**：补齐依赖、搭目录、约定 `prototypes/`、`git init`、把模板 `graph.py` 重构为可扩展模块骨架（仅占位，不实现业务逻辑）。
- **范围**：pyproject 增补依赖（chroma / 选定 LLM SDK / langgraph-checkpoint-sqlite / fastapi 等）、`data/` 目录骨架（`markdown/`、占位样例）、`src/agent/` 模块拆分占位（`indexing/` `retrieval/` `subgraphs/` `graph.py` 等）。
- **不做**：不实现任何检索/RAG/决策逻辑。
- **验收**：`langgraph dev` 仍可启动；`make lint` 通过；git 仓库就绪并有首次提交。

### Phase 1 — Index Agent 与本地知识库基础设施
- **目标**：① markdown 行级切片（保留 `start_line`/`end_line`）；② Index Agent 维护 `index.json` + Chroma 两 collection（`domain_kb`/`interview_kb`）向量灌入；③ 三路检索原语（vector / index / grep）。
- **范围**：
  - `src/index_agent/`（`graph.py`/`state.py`/`tools/`）——**后台 agent**，含可被导入接口 / CLI 唤醒的入口（前端未实现阶段提供主动唤醒命令）。
  - 三路检索原语放 `src/rag_agent/tools/`（本阶段先实现原语函数 + 单测，Phase 2 再组装子图）。
  - `prototypes/phase1_retrieval.py` 验证检索返回行区间。
- **不做**：不组装 `rag_agent` 子图、不接主图 LLM、不做重排合并、不做前端导入接口（仅 CLI 唤醒）。
- **验收**：单测通过；CLI 唤醒 Index Agent 处理 `data/markdown/` 样例后产出 `index.json` + 向量库；原型脚本对样例返回带 `[文件名](start~end)` 的片段。
- **定位提醒**：Index Agent 不进 `AgentRegistry`、不在主图流程中，主图只读其产出（`index.json` / Chroma）。

### Phase 2 — 混合 RAG 子图
- **目标**：组装三路检索 + 行区间去重合并（重排）+ `citations_output`（带行号引用）+ `gap_topic` 判定；定义 `RAGState` schema 并编译为子图。
- **范围**：`src/rag_agent/`（`graph.py` 图逻辑 / `state.py` `RAGState` / `tools/` 三路检索工具）；可选在 `langgraph.json` 注册子图入口便于 Studio 调试。
- **不做**：不接主图、不做 Memory、不做深研。
- **验收**：Studio 输入 `{query, search_type}`，看到 `citations_output` 含文件名+行区间；低分场景输出 `gap_topic`。

### Phase 3 — 动态主图总线（结构化决策路由）
- **目标**：`AgentRegistry` + `chat_node`（`AgentAction` 结构化输出：chat/tool/sub_agent）+ `tool_dispatcher_node` + `main_dynamic_router` + `build_main_graph`；将 RAG 子图作为首个子智能体接入（槽位隔离）。`AgentAction.sub_agent_name` 的候选集此时含 `rag_agent`（后续 Phase 5 加 `resume_agent`、Phase 6 加 `research_agent`）。
- **范围**：`src/agent/registry.py`、`src/agent/graph.py`（主图）；`src/rag_agent/` 的 wrapper 接入（通过主图 wrapper 节点 + 槽位引用 `rag_agent` 子图，不在主图内复刻其逻辑）。`MainState` 含 `messages`/`citations`/隔离槽位。
- **不做**：不做 Memory、不做 SQLite 持久化（用内存 checkpointer）、不做深研、不做简历子图、不做 FastAPI。
- **验收**：Studio 端到端——提问→`chat_node` 决策唤醒 `rag_agent`→分发→子图检索→返回系统上下文→`chat_node` 生成带引用的最终回复。

### Phase 4 — 本地 SQLite 断点 + 长期记忆
- **目标**：`SqliteSaver` 作 checkpointer（`sqlite_checkpoints.db`）、本地 SQLite `Store`（用户画像）、Memory 子图（静默提取用户偏好/弱点/简历优化方向）。
- **范围**：`src/memory_agent/`（`graph.py`/`state.py`/`tools/`，长期记忆提取子图）、`src/agent/persistence.py`（SqliteSaver + Store 配置）、主图 `load_memory_node`/`save_memory_and_end_node` 接入。
- **不做**：不做 FastAPI、不做深研。
- **验收**：中断后 `app.get_state_history()` 可重放崩溃前状态；Store 中存有提取的用户画像；Studio 跨会话记忆生效。

### Phase 5 — FastAPI 端到端 + 简历优化子图
- **目标**：① FastAPI `/v1/chat`（接收 `user_id`/`thread_id`，SSE 流式）；② **简历优化子图 `resume_agent`**（草稿暂存/回退，版本栈持久化到 Store 按 `user_id`）；③ 主图 router 识别"优化简历"意图→激活 `resume_agent` 子智能体；④ 端到端集成测试。
- **范围**：`src/resume_agent/`（`graph.py`/`state.py`/`tools/`，简历优化子图，含草稿版本栈工具）、`src/agent/server.py`（FastAPI app）、简历模板数据、集成测试。
- **不做**：不做自主深研。
- **验收**：脚本/Postman 多次调用 `/v1/chat`；简历优化多轮交互 + 草稿暂存/回退可用；流式输出正常；router 正确把简历请求路由到 `resume_agent`。

### Phase 6 — 自主深研 HITL（收尾）
- **目标**：Deep Research 子图——`gap_topic`→生成深研大纲→`interrupt()` 等用户批准→获批后多轮 web 爬取→写新 Markdown→**经导入接口 / CLI 唤醒 Index Agent** 重建 `index.json` + 向量灌入（不走主图节点）。
- **范围**：`src/research_agent/`（`graph.py`/`state.py`/`tools/`，含 `interrupt` 与 web 检索工具）、主图 `research_*` 槽位接入、深研完成后触发 Index Agent 唤醒入口。
- **验收**：端到端——RAG 判定 `gap_topic`→主图挂起→用户批准→新资料入库→唤醒 Index Agent 重建索引→后续问答可命中新资料。

## 四、贯穿各阶段的硬约束（来自设计文档 + 用户约定，不可降级）

- **行级引用硬约束**：知识库切片必须在 metadata 保留 `start_line`/`end_line`，检索结果必须附带文件名+行区间。
- **状态隔离**：主图与子图仅通过预留 input/output 槽位交互，不直接交叉污染。
- **可拔插注册**：新增子智能体走 `AgentRegistry` + 槽位 + wrapper，不直接堆节点。
- **子智能体目录结构（硬性约定）**：每个子图 / 子 agent 的相关逻辑**全部集中到 `src/` 下独属文件夹**，不散落到主图或公共模块。文件夹名 = 子 agent 名 = `AgentRegistry` 注册名。文件夹内大致结构：
  - `graph.py` — 该智能体图逻辑（节点、边、编译）。
  - `state.py` — 该智能体状态及数据结构定义。
  - `tools/` — 该智能体可使用的工具（按需分子模块）。
  - 其余辅助模块（`prompts.py`/`retrieval.py` 等）按需新增，务必自包含。
  - 主图 `src/agent/graph.py` + `src/agent/registry.py` 仅通过 wrapper + 槽位引用子图，不实现子图内部逻辑。
  - 现有子 agent 命名：`rag_agent`（Phase 1-2）、`resume_agent`（Phase 5）、`research_agent`（Phase 6）、`memory_agent`（Phase 4）。
- **Lint/类型**：`make lint`（ruff + mypy `--strict`）须通过；CI 在 Python 3.11/3.12 校验。
- **Studio 优先调试**：每阶段用 `langgraph dev` + Studio 验证节点轨迹与中间状态。
