# 简历展示与本机演示实施计划

## 1. 最终目标

本轮不部署前端、不部署后端，也不引入 Docker、云数据库、公网隧道或跨域适配。

只交付两个成果：

1. 一个可靠的本机一键启动入口，面试前无需重新记忆或拼接启动命令；
2. 一份面向招聘者的高质量 README，通过文字、截图、GIF 和架构图完整介绍项目能力。

```text
GitHub README
├── 项目定位与核心亮点
├── 功能截图和演示 GIF
├── Agent 图结构与前后端架构
├── 一分钟演示路径
└── 本机运行说明

本机现场演示
└── demo.cmd → FastAPI → 托管 frontend/dist → 自动打开浏览器
```

## 2. 明确不做的内容

- 不创建独立的前端宣传页；
- 不部署 Vercel、Render、Railway 或其他云服务；
- 不实现“后端离线”公网状态页；
- 不引入 Cloudflare Tunnel、Tailscale Funnel 或反向代理；
- 不迁移 PostgreSQL、对象存储或云向量库；
- 不为了部署改造当前同源 Cookie、SSE 和游客身份协议；
- 不公开 Swagger 接口。

已有的部署分析文档可作为未来参考，但不再进入当前实施范围。

## 3. 阶段一：本机一键启动

### 3.1 目标体验

首次完成环境安装和前端构建后，日常演示只需在仓库根目录双击：

```text
demo.cmd
```

启动器应当：

1. 定位项目根目录，不依赖用户当前终端路径；
2. 检查 `.venv`、Python 入口和 `frontend/dist`；
3. 检查端口是否已被占用；
4. 使用现有虚拟环境直接启动 Uvicorn，避免 `uv` 每次解析环境；
5. 固定使用单 worker，符合当前进程内任务控制约束；
6. 等待 `/health` 成功后自动打开浏览器；
7. 在窗口内按 `Ctrl+C` 即可停止；
8. 支持 `-NoBrowser` 和 `-Port` 两个可选参数；
9. 失败时给出明确、可执行的修复提示，不自动安装依赖或改写数据。

### 3.2 当前基础

仓库中已经形成第一版：

- `demo.cmd`：双击入口；
- `scripts/start_demo.ps1`：环境检查、服务启动和浏览器打开逻辑。

正式收尾前需要完成：

- PowerShell 语法验证；
- 缺少 `.venv`、缺少前端产物、端口占用三个失败分支验证；
- 临时端口启动、`/health` 和首页访问验证；
- `Ctrl+C` 后确认端口释放；
- 确认脚本不修改知识库、简历、checkpoint 和产品事件数据；
- 将首次准备与日常启动在 README 中清楚分开。

## 4. 阶段二：README 作品集化

README 是唯一的线上展示入口，不再制作另一套展示页面。

### 4.1 首屏

招聘者在不滚动或只滚动一次的范围内应看到：

- 项目名称；
- 一句话定位；
- 一张产品总览图或 15～25 秒 GIF；
- Main、RAG、Research、Resume 多智能体能力摘要；
- “一分钟了解项目”和“本机运行”入口；
- 明确说明这是可运行的个人作品原型，而非线上 SaaS。

### 4.2 已实现功能

按用户价值而不是代码模块组织：

1. **统一多 Agent 对话**
   - 用户与不同 Agent 的头像；
   - 工具调用、任务状态和 Agent 交接；
   - 基于稳定事件 ID 的产品时间线。
2. **RAG 问答**
   - 语义/关键词双检索；
   - 行级来源；
   - 只引用回答真正使用的资料。
3. **深度研究**
   - 计划审批；
   - 关键词、URL、抓取与提炼进度；
   - 报告完成后的知识入库审批。
4. **简历修改**
   - Main Agent 选择和交接简历；
   - Resume Agent 计划—确认—修改循环；
   - 全文源码 Diff、Lapis 渲染对比和逐条审批；
   - 保存为新简历，永不覆盖源文件。
5. **可靠运行**
   - checkpoint 中断恢复；
   - `operation_id` 防止操作混淆；
   - 独立 `interrupt_id` 防止审批串用；
   - 产品事件只负责展示，不参与图执行。
6. **数据与配置隔离**
   - Thread、简历、知识和状态按 principal 隔离；
   - 公共/个人知识管理；
   - 游客运行时模型配置与本地开发人员模式。

### 4.3 图示

README 至少保留三张逻辑图：

1. **系统架构图**：React → FastAPI → LangGraph → 持久化层；
2. **Main Agent 图结构**：`chat_node`、工具路由及 RAG/Research/Resume wrapper；
3. **Resume Agent 核心状态流**：计划确认、逐条修改审批、待命、保存/放弃退出。

如一张图过于复杂，可以补充：

- Research Agent 的两次 Interrupt；
- checkpoint 与产品事件时间线的职责分离图。

图中只描述当前真实代码，不展示尚未实现的未来设计。

### 4.4 工程说明

README 后半部分包含：

- 技术栈；
- 首次安装；
- `demo.cmd` 日常启动；
- 开发调试命令；
- 持久化文件说明；
- 测试命令；
- 当前边界与未来方向。

部署文档不再作为 README 的主要阅读路径，避免招聘者误以为项目必须先部署才能体验。

## 5. 展示素材

### 5.1 需要你制作的素材

| 文件 | 内容 | 形式 |
|---|---|---|
| `demo-overview.gif` | 新建会话、Agent 回复、打开简历工作区 | 15～25 秒 GIF |
| `chat-timeline.png` | 多 Agent 头像、任务状态和工具卡片 | PNG |
| `rag-citations.png` | RAG 回答与实际引用资料 | PNG |
| `deep-research.gif` | 计划、URL、研究进度和入库确认 | 20～30 秒 GIF |
| `resume-workspace.png` | 会话管理、工作区、聊天区三栏布局 | PNG |
| `resume-diff.gif` | 源码 Diff 与 Lapis 修改前后预览 | 15～20 秒 GIF |
| `checkpoint-recovery.gif` | 中断、重新进入会话、恢复执行 | 10～15 秒 GIF |
| `knowledge.png` | 公共/个人知识管理 | PNG |

统一放入：

```text
docs/assets/
```

### 5.2 录制要求

- 使用虚构或脱敏简历；
- 不显示 `.env`、API Key、开发口令、真实邮箱和手机号；
- 建议浏览器内容区宽度统一为 1440 或 1600 像素；
- GIF 删除模型等待时间，突出状态变化，但不伪造结果；
- 单个 GIF 尽量控制在 12 MiB 以内；
- 每个素材只讲一个亮点；
- 截图前清理无关测试 Thread 和失败提示。

## 6. 双方分工

### 6.1 Codex 负责

- 验证并完善一键启动脚本；
- 根据真实代码核对 README 中的功能描述；
- 绘制 Mermaid 架构图和 Agent 状态图；
- 调整 README 的信息层级、文字和素材位置；
- 为缺失素材保留明确占位说明；
- 素材加入后检查路径、尺寸和 GitHub 渲染效果；
- 运行与本次改动相称的脚本、前端构建和后端检查；
- 用户验收后按指引进行 Git 存档。

### 6.2 你需要完成

1. 准备一份脱敏的 Markdown 演示简历；
2. 准备三个稳定的演示问题：普通 RAG、深度研究、简历修改各一个；
3. 按第 5 节录制截图/GIF，并放进 `docs/assets/`；
4. 告知希望在简历中使用的项目名称和一句话描述；
5. 审核 README 是否存在技术表述夸大或与你预期不一致；
6. 在自己的 Windows 环境双击 `demo.cmd` 完成最终验收；
7. 确认后指示 Git 提交。

## 7. 实施顺序

严格按以下顺序推进：

1. 确认本计划；
2. 在 `prototypes/` 验证一键启动的关键失败和退出场景；
3. 双方确认启动器行为；
4. 正式完善启动器；
5. 核对真实图结构和功能实现；
6. 正式重写 README 并补齐 Mermaid 图；
7. 你制作并加入展示素材；
8. Codex 完成素材排版和链接检查；
9. 你执行本机启动与 README 验收；
10. 按你的指引进行 Git 存档。

## 8. 完成标准

- 首次安装完成后，双击 `demo.cmd` 可以稳定启动完整系统；
- 启动失败时能明确说明原因，停止后不残留监听进程；
- README 首屏能在一分钟内说明项目解决什么问题、实现了什么能力；
- README 的功能、Agent 图和数据流均与当前代码一致；
- README 包含真实、脱敏且易读的功能截图/GIF；
- 招聘者无需部署项目，也能仅通过 GitHub README 理解技术深度；
- 现场需要真实操作时，可以在本机快速完成演示；
- 本轮不新增任何公网部署和云运维负担。
