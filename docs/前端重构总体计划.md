# 前端重构总体计划

> 状态：总体计划草稿，等待用户评审
>
> 依据：[前端重构需求分析.md](前端重构需求分析.md)
>
> 本项目后续不采用 OpenSpec 工作流。本计划遵循仓库 `AGENTS.md`：总体计划先经用户认可；每个阶段开始正式实现前，必须先完成边界陈述与 `prototypes/` 快速原型，并持续协商至细节无异议，再请求用户批准开发。

## 1. 重构目标

本轮重构要把当前本地单会话原型升级为可部署的桌面端 Web 产品，同时保留现有 LangGraph 多智能体框架。

核心目标：

1. 使用 React 重构前端，建立统一、可恢复的产品级交互状态。
2. 实现游客隔离与多 Thread 会话管理。
3. 保留 Main Agent、Resume Agent、Research Agent 的独立状态，通过结构化交接保证上下文连续。
4. 建立产品级统一事件时间线，支持多 Agent 头像、消息来源、任务进度和 Interrupt 恢复。
5. 将 Resume Agent 做成唯一使用中间工作区的功能。
6. 展示 Research Agent 的计划、关键词、网页 URL、抓取与提炼进度。
7. 新增个人知识库管理，并实现游客级知识库隔离。
8. 深研完成后由 Interrupt 询问用户是否加入个人知识库。
9. 支持用户提供自己的 API Key，后端只在执行内存中使用，不持久化。
10. 离开或切换会话时中断当前任务，重新进入后从最近 checkpoint 恢复。
11. 提供受控开发人员模式，使本地 React/FastAPI 调试与 LangGraph Studio 可以直接使用 `.env` 配置。

## 2. 本轮非目标

- 不实现普通用户注册、登录、密码找回和跨设备账户同步；开发人员模式是受控开发入口，不是完整账户系统。
- 不实现移动端布局。
- 不允许多个会话同时运行长任务。
- 不实现 Skill 安装，但数据隔离和能力配置需要为未来 Skill 预留用户边界。
- 不支持 PDF、DOCX 简历导入或导出。
- 不在本轮重新设计 Resume Agent 的逐条审批机制。
- 不实现已审批修改的撤销。
- 不提前创建后续阶段才需要的模块、空文件或占位接口。

## 4. 关键架构原则

### 4.1 三种状态分离

必须区分：

1. **Agent State**：LangGraph 节点执行和模型上下文。
2. **Product Event Timeline**：用户看到的消息、进度、模式切换和审批历史。
3. **Frontend View State**：侧栏折叠、选中页签、滚动位置等纯界面状态。

产品时间线不能继续通过临时拼接各 Agent 的 `messages` 获得。

### 4.2 Agent 独立与结构化交接

- Main Agent 和 Resume Agent 不共享完整消息列表。
- Main → Resume 传结构化任务简报。
- Resume → Main 返回结构化执行结果。
- 前端时间线保持连续，并明确显示 Agent 头像和名称。

### 4.3 游客身份不是认证

第一版游客身份只用于资源分区，不提供安全账户能力：

- 浏览器首次访问生成稳定随机 `guest_id` 或不透明访客令牌。
- 所有 Thread、事件、知识库资源都归属该游客。
- 服务端不能信任客户端提交的任意资源归属字段，必须统一校验访问边界。
- 清除浏览器数据可能导致游客无法再次访问旧资源；界面需要明确提示。

### 4.4 开发人员模式

- LangGraph Studio 继续直接读取 `.env`，无需启动前端或填写 API Key。
- React/FastAPI 本地联调时允许创建开发人员会话，由后端为该会话使用 `.env` 模型配置。
- 开发人员身份必须由服务端能力开关和受控凭证确认，不能信任客户端自报身份。
- 开发人员的 Thread、事件、知识库和未来 Skill 使用独立开发作用域。
- 生产环境默认禁用；非本机环境开启时必须增加访问凭证与网络限制。
- 后端不得把 `.env` 中的 API Key 返回给浏览器。

### 4.5 API Key 边界

- API Key 存在浏览器会话存储，不使用 Cookie 自动携带。
- 仅通过 HTTPS 请求头提交给需要模型执行的请求。
- 后端只放入短生命周期运行上下文。
- 不写入数据库、checkpoint、Store、产品事件和日志。
- Interrupt 恢复时由浏览器重新提交。
- 任何诊断信息必须脱敏。

### 4.6 单活动长任务

- 一个游客同一时间最多运行一个长任务。
- 切换会话或离开页面时请求中断当前任务。
- 系统只承诺从 LangGraph checkpoint/超级步边界恢复，不假设任意节点能从内部暂停位置继续。
- 中断时未完成的节点或同一未完成超级步中的多个节点，允许在恢复后整体重跑。
- 搜索和抓取等操作允许重复执行；文件写入、索引和删除等操作需要保证重跑后的最终结果一致。

## 5. 建议前端技术基线

以下是计划建议，需在前端基础阶段协商后批准：

- React + TypeScript。
- Vite 作为开发和构建工具。
- React Router 管理会话、知识库和设置路由。
- 自定义 `fetch + ReadableStream` SSE 客户端，或选择支持 POST SSE 的轻量库。
- 服务端数据与界面状态分离管理；是否引入 TanStack Query、Zustand 等依赖在快速原型后决定。
- CSS 方案优先考虑易维护的设计 token + 组件样式；是否使用 Tailwind 或组件库在视觉原型阶段决定。
- Agent 头像与状态图标优先使用代码原生 SVG/Icon，不使用生成式位图作为核心 UI 依赖。

依赖均按阶段按需提示用户通过项目约定的包管理方式安装，不提前安装。

## 6. 目标路由与页面

建议路由：

```text
/                         默认进入最近会话或欢迎页
/threads/:threadId        会话页面
/knowledge                个人知识库
/settings/models          模型与 API Key 设置
```

Resume Agent 不再使用独立 `/resume` 页面。其工作区作为会话页内的条件区域出现。

第一版不创建 Skill 管理页，只在后端数据边界和文档中预留未来能力。

## 7. 目标后端能力清单

具体路径和 schema 要在接口阶段原型后确认，能力上至少需要：

### 7.1 游客与会话

- 创建或恢复游客身份。
- 在服务端允许时创建受控开发人员会话。
- 创建会话。
- 列出当前游客的会话。
- 读取、重命名、删除会话。
- 读取会话运行状态。
- 校验游客、开发人员及其资源作用域。
- 中断会话执行。
- 从最近 checkpoint 恢复。

### 7.2 产品事件

- 分页读取会话事件。
- 订阅本轮实时事件。
- 事件具备稳定 ID、顺序、来源 Agent、类型和任务关联。
- 支持消息、状态、模式切换、进度、Interrupt、用户决策、错误和完成事件。

### 7.3 Agent 执行

- 启动用户消息。
- 恢复 Interrupt。
- 传入运行时 API Key 与模型配置。
- 停止生成或长任务。
- 拒绝同一游客并发启动第二个长任务。

### 7.4 知识库

- 上传 Markdown。
- 列出文件与索引状态。
- 删除文件及相关向量。
- 重建索引。
- 查询任务进度。
- 用户确认后导入深研结果。
- 检索时同时支持公共知识库与当前游客个人知识库，并保证资源隔离。

## 8. 产品事件模型草案

事件模型需要先通过原型验证，不在总体计划中锁死字段。概念类型包括：

```text
message.user
message.agent
agent.transition
tool.status
research.plan
research.progress
research.source
interrupt.requested
interrupt.resolved
resume.diff
task.completed
task.failed
task.cancelled
```

事件应支持：

- 恢复后去重。
- SSE 断线重连。
- 同一事件增量更新或后续事件替代。
- Agent 头像与名称映射。
- 不包含 API Key、模型请求头或敏感调试数据。

## 9. 分阶段重构计划

每阶段均需单独获得用户批准后才开始正式实现。

### 9.1 基于当前后端的逐阶段判断

当前后端不是一套可以由新前端直接消费的稳定 API。它已经具备 LangGraph 主图、子图、SSE 和 Interrupt 基础，但仍是单进程、单游客、单知识库和全局模型配置。因此，本轮不是“先写完前端，最后补几个接口”，而是前端与后端按能力切片共同演进。

| 阶段 | 后端是否修改 | 强度 | 判断依据 |
|---|---|---:|---|
| 阶段 0：风险探针 | 不改正式后端 | 原型 | 先验证取消、恢复、运行时 Key、子图事件和知识库隔离，避免错误方案进入 `src/` |
| 阶段 1：身份模式与 Thread | 必须 | 核心 | 当前 `/v1/thread` 只在进程内保存一个 `current_thread_id`，没有会话表、游客归属、开发人员模式和资源授权 |
| 阶段 2：产品事件 | 必须 | 核心 | 当前 SSE 只有 `token/interrupt/done`，历史通过挖 LangGraph state 恢复，没有稳定产品事件或去重 ID |
| 阶段 3：React 普通聊天 | 需要 | 中等 | 需要稳定错误协议、停止接口、CORS/部署边界和新事件协议；不能只替换 HTML |
| 阶段 4：Agent 交接 | 必须 | 核心 | Main → Resume 当前只传 `intent`，Resume → Main 只回摘要与最终简历，没有结构化双向交接 |
| 阶段 5：Resume 工作区 | 需要 | 中等 | 图主体可保留，但 Interrupt、可恢复工作区快照、edit 标识和旧 `/resume` 跳转需要重构 |
| 阶段 6：Research 进度 | 必须 | 核心 | 当前 `search_node` 串行包办搜索/抓取/提炼，无法细粒度流式展示；`finalize_node` 在用户确认前已写文件 |
| 阶段 7：个人知识库 | 必须 | 核心且范围最大 | 当前所有路径、`index.md`、Chroma collection 和检索缓存均为全局单例，无游客隔离 |
| 阶段 8：API Key | 必须，且底座需前置 | 核心 | 当前 `get_chat_model` 从全局环境变量取 Key，各 Agent 还缓存模块级 LLM，无法安全支持游客独立凭据 |
| 阶段 9：中断恢复收尾 | 必须 | 中等至核心 | 当前只有 checkpoint 续跑，没有主动取消、活动任务锁、幂等恢复和断线语义 |

### 9.2 当前后端中可以保留的部分

以下能力原则上不需要推倒重写：

- Main Agent 的 registry + wrapper 布线模式。
- LangGraph 父图调用子图并透传 Interrupt 的基本机制。
- Checkpointer 驱动的 Thread 恢复机制。
- Resume Agent 的常驻编辑会话与逐条审批主流程。
- RAG 的语义/关键词双管道和行级引用数据结构。
- Index Agent 的切片、向量写入和 `index.md` 更新算法。
- Research Agent 的计划、搜索、抓取、提炼和总结能力。

重构重点是给这些能力增加产品级边界、用户隔离、可观察事件和安全运行时配置，而不是为了 React 重写所有 Agent。

### 9.3 API Key 阶段的前置约束

虽然完整模型设置页面列在阶段 8，但后端运行时凭据底座不能等到阶段 8 才建设。阶段顺序按以下方式处理：

1. 阶段 0 先验证 API Key 通过 `RunnableConfig` 或受控请求上下文传入主图与所有子图，且不进入 checkpoint。
2. 阶段 1–2 的请求、事件和日志 schema 从一开始禁止包含凭据字段。
3. 阶段 3 普通聊天正式联调前，实现最小运行时模型配置注入，并移除会导致游客间串用的模块级 LLM 凭据缓存。
4. 阶段 8 再实现完整设置页、连接测试、浏览器会话存储和安全审计。

这属于阶段 3 普通聊天真实运行所需的后端能力，不是为后续提前创建占位。

### 9.4 各阶段涉及的现有后端模块

#### 阶段 0

- `src/server/app.py`：仅作为探针调用对象，不修改正式文件。
- `src/kernel/llm.py`：验证运行时配置能否替代全局环境变量。
- `src/agents/{main,resume,research}/`：验证子图配置继承和取消边界。
- `src/agents/{rag,index}/`：验证游客知识库隔离策略。

#### 阶段 1

- `src/server/app.py`：移除进程级 `current_thread_id` 语义，接入游客和 Thread 服务。
- `src/kernel/persistence.py`：明确 Thread checkpoint、Store 与产品元数据的持久化边界。
- 增加由服务端控制的开发人员模式入口和独立开发作用域，客户端不能仅凭请求字段升级身份。
- 新增本阶段实际需要的游客/Thread 数据访问模块；不创建事件、知识库或 Skill 占位模块。

#### 阶段 2

- `src/server/app.py`：从临时 SSE 序列化升级为统一事件输出和历史读取。
- `src/kernel/contracts.py`：继续只负责 Agent/前端业务契约，或拆分产品事件契约；具体由原型决定。
- 新增事件持久化模块和事件 schema。
- `src/agents/main/graph.py` 与 wrapper：在明确的业务节点产生模式和任务事件，避免从 token 猜测全部状态。

#### 阶段 3

- `src/server/app.py`：补稳定错误、停止请求、CORS 与 React 部署边界。
- `src/kernel/llm.py`、`src/kernel/config.py`：实现最小运行时模型配置，环境变量只保留本地开发兜底。
- `src/agents/main/graph.py`、`src/agents/resume/graph.py`、`src/agents/research/graph.py`：消除绑定游客凭据的模块级 LLM 单例，改为请求/运行时安全获取。
- RAG 后端算法本阶段原则上不改，只对接新事件和游客上下文。

#### 阶段 4

- `src/agents/main/tools/resume_agent.py`：把单一 `intent` 扩展为结构化任务简报，并返回结构化结果。
- `src/agents/main/state.py`、`src/agents/resume/state.py`：只增加本阶段交接真正需要的字段。
- `src/agents/main/prompts.py`、`src/agents/resume/prompts.py`：约束任务简报生成和消费。
- `src/server/app.py` 或会话服务：持久化 `active_mode/active_agent`，校验输入路由。

#### 阶段 5

- `src/agents/resume/graph.py`：补稳定 edit ID、展示元数据和可恢复工作区信息；不重写逐条审批主流程。
- `src/agents/resume/state.py`：保存当前编辑展示所需的最小状态。
- `src/kernel/contracts.py`：将 Resume Interrupt 对齐 React 交互。
- `src/server/app.py`：停止依赖 `_extract_subgraph_state` 猜测页面状态，改用正式会话/事件接口。
- 旧 `/resume` 和静态页面在本阶段验收后退役。

#### 阶段 6

- `src/agents/research/graph.py`：把当前单个 `search_node` 拆成可 checkpoint、可报告进度的步骤；把生成报告与写入知识库分离。
- `src/agents/research/state.py`：增加来源状态、进度和待入库产物。
- `src/kernel/contracts.py`：新增“是否加入个人知识库”Interrupt 契约。
- `src/agents/main/tools/research_agent.py`：返回结构化研究结果和入库状态。
- `src/agents/research/graph.py` 不再直接在确认前写 `MARKDOWN_DIR`，也不应继续无条件跨子图调用 Index Agent。

#### 阶段 7

- `src/kernel/paths.py`：从全局固定路径演进为安全的游客资源解析。
- `src/kernel/embedder.py`：重新定义 collection 命名或隔离策略。
- `src/agents/index/`：所有扫描、写入、删除和重建操作携带知识库作用域。
- `src/agents/rag/tools/retrieval.py`：移除全局 collection 单例假设，查询公共库与当前游客个人库。
- `src/agents/research/graph.py`：通过正式知识库导入服务提交已确认产物，不直接写全局目录或调用 Index 子图。
- 新增知识库 API 与归属校验。

#### 阶段 8

- `src/kernel/llm.py`、`src/kernel/config.py`：完成 provider/base URL/model/key 的运行时配置与校验。
- 所有 LLM 调用节点：统一从运行时上下文取配置，禁止重新引入全局可变凭据。
- `src/server/app.py`：读取敏感请求头、脱敏错误并确保中间件不记录 Key。
- 新增连接测试接口，但不得保存 Key。

#### 阶段 9

- `src/server/app.py`：实现取消、恢复、幂等和断线处理。
- Thread/任务服务：实现单游客活动任务锁和状态迁移。
- 各长任务节点：在安全边界响应取消；不能安全中断的同步调用需记录明确语义。
- Checkpointer：验证并规范从最近 checkpoint 恢复，而不是重复执行已完成的外部副作用。

### 阶段 0：关键风险探针

#### 目标

在不修改正式代码的前提下，验证会影响总体方案的关键技术风险。

#### 快速原型

统一放入 `prototypes/`：

1. **取消与恢复探针**：测试 SSE 客户端断开、任务取消、节点完成与 checkpoint 恢复的真实行为。
2. **嵌套子图事件探针**：验证 Main/Resume/Research namespace 到统一事件来源的稳定映射。
3. **API Key 生命周期探针**：验证请求级运行时配置能否贯穿主图与子图，同时不进入 checkpoint。
4. **游客知识库隔离探针**：比较独立 collection 与共享 collection + 强制 owner filter 的隔离和维护成本。
5. **React SSE 状态探针**：最小 React 页面验证 POST SSE、断线、事件去重和恢复。

#### 产出

- 原型脚本与运行记录。
- 关键决策表。
- 修订后的事件、凭据和隔离方案。

#### 验收

- 已明确“自动中断”的实际边界：从 checkpoint/超级步恢复，未完成节点允许整体重跑。
- 明确 API Key 如何进入 LangGraph 运行时。
- 明确知识库物理隔离方案。
- 明确 SSE 事件恢复策略。

### 阶段 1：身份模式与多 Thread 基础

#### 目标

把进程级单 `thread_id` 改造成带游客模式、受控开发人员模式和资源作用域的多会话系统，不改 Agent 业务行为。

#### 后端范围

- 游客标识解析与校验。
- 开发人员模式开关、受控入口与身份确认。
- 开发人员作用域与游客作用域隔离。
- Thread 元数据持久化。
- 创建、列表、读取、重命名、删除接口。
- Thread 所有权校验。
- 单游客活动任务锁的基础模型。
- 兼容现有 LangGraph checkpointer 的 thread 配置。

#### 前端原型

- 左侧会话列表原型。
- 新建、切换、重命名和删除交互。
- 游客数据清除风险提示。
- 仅在服务端允许时显示开发人员入口和“使用开发环境配置”状态。

#### 正式实现验收

- 两个游客不能访问彼此 Thread。
- 游客不能把自己声明为开发人员，也不能使用服务端 `.env` 凭据。
- 开发人员模式关闭时相关入口不可用；开启时浏览器仍看不到 `.env` 密钥。
- 同一游客可以创建和恢复多个 Thread。
- 删除会话不会误删其他游客数据。
- ruff、mypy `--strict` 与精简测试通过。

### 阶段 2：统一产品事件时间线

#### 目标

建立与 LangGraph `messages` 解耦的持久化产品事件模型。

#### 后端范围

- 事件存储与顺序规则。
- Agent 来源映射。
- 历史事件分页读取。
- SSE 统一事件 envelope。
- Interrupt、完成、失败与取消事件。
- 旧 SSE 协议的迁移策略。

#### 前端原型

- 用静态事件数据验证统一时间线。
- 用户消息右置。
- Main、Resume、Research 左置头像。
- 模式切换分隔条。
- 工具和进度卡片。
- 刷新后事件去重。

#### 正式实现验收

- 刷新不会丢失或重复消息。
- Main 与 Resume 消息在同一时间线中连续显示。
- 产品事件不包含 API Key。
- 老 checkpoint 缺少事件时有明确兼容或迁移行为。

### 阶段 3：React 应用壳与普通聊天

#### 目标

建立 React 正式工程，替换主页原生 HTML/JS，实现会话管理和普通聊天闭环。

#### 前端范围

- React 路由与应用壳。
- 左侧会话管理。
- 右侧统一聊天区。
- Agent 头像和消息分组。
- 输入框、流式输出、停止、错误与重试。
- RAG 引用折叠展示。
- 桌面端自适应宽度。

#### 后端范围

- 补齐前端所需事件和错误协议。
- 提供前端构建产物的部署或反向代理边界。
- 落地阶段 0 已验证的最小运行时模型配置注入，使普通聊天能够使用当前游客请求携带的模型配置。
- 移除可能绑定全局 API Key 并在游客之间复用的模块级 LLM 实例缓存。
- 保证请求头中的 API Key 不进入日志、事件、Agent state 或 checkpoint。

#### 正式实现验收

- 普通聊天与 RAG 闭环可用。
- 多会话创建、切换和恢复可用。
- 用户消息右侧、Agent 消息左侧且身份清晰。
- 原生 `static/index.html` 的退役策略明确。

### 阶段 4：多 Agent 交接契约

#### 目标

在不合并 Agent 内部消息历史的前提下，实现 Main ↔ Resume 的上下文连续。

#### 后端范围

- Main → Resume 结构化任务简报。
- Resume → Main 结构化结果。
- 会话 `active_mode` 与 `active_agent`。
- Agent 进入和退出事件。
- Resume 模式下输入路由约束。
- Resume 模式中无关问题的提示策略。

#### 前端原型

- Main Agent 消息 → 模式分隔条 → Resume Agent 消息。
- 输入框接收者提示。
- Agent 切换后历史不清空。

#### 正式实现验收

- Resume Agent 能获得目标岗位、约束和相关上下文。
- Main Agent 能获得简历任务结果。
- 用户能清楚理解当前由哪个 Agent 响应。
- 刷新后活动 Agent 与输入路由正确。

### 阶段 5：Resume 工作区

#### 目标

将现有独立 `/resume` 页面改造成会话页中间工作区。

#### 前端范围

- Markdown 文件选择与本地读取。
- 中间工作区展开和关闭。
- Markdown/预览视图。
- 当前修改定位。
- 红绿 Diff。
- 修改序号、章节和理由。
- 计划确认、接受、拒绝和建议。
- 文本选区传递。
- 导出最终 Markdown。
- 不可撤销提示。

#### 后端范围

- Resume interrupt 与统一事件对接。
- 可恢复的工作区快照。
- 当前 edit 的稳定标识和展示信息。
- 移除对旧页面跳转的依赖。

#### 正式实现验收

- 全流程不发生页面跳转或聊天清空。
- 刷新后恢复文件、当前 Diff 和审批状态。
- 已审批修改不可撤销，但可发起新的修改请求。
- 后端仍不读写用户本地文件。

### 阶段 6：Research 详细进度与知识库确认

#### 目标

把 Research Agent 的内部步骤转换为用户可理解、可恢复的聊天任务卡片。

#### 后端范围

- 计划、关键词、URL、抓取、提炼和报告事件。
- 单个来源的状态与失败原因。
- 停止研究。
- 研究完成后的知识库确认 Interrupt。
- 用户拒绝时不写入知识库。
- 用户批准时本阶段只记录授权与待导入状态；实际个人知识库持久化和索引由阶段 7 的正式导入服务完成。

#### 前端范围

- Research Agent 头像。
- 计划确认卡片。
- 可折叠研究进度卡。
- URL 列表和状态。
- 总体进度。
- 失败与重试提示。
- 是否加入知识库的确认卡片。

#### 正式实现验收

- 研究过程详细但不打开中间工作区。
- 刷新后恢复当前研究阶段。
- 未经确认绝不写入个人知识库。
- 停止后状态明确且可以从安全 checkpoint 恢复或重新开始。

### 阶段 7：个人知识库管理与隔离

#### 目标

提供本轮范围内的知识库页面和完整游客隔离。

#### 前端范围

- Markdown 上传。
- 文件列表。
- 公共/个人来源标识。
- 索引状态和失败状态。
- 删除与重新索引。
- 深研资料标识。

#### 后端范围

- 游客级文件存储边界。
- Chroma 与 `index.md` 的用户隔离。
- 上传、列表、删除、重建和状态接口。
- Index Agent 的非对话调用入口。
- RAG 同时检索公共库和当前游客个人库。
- 删除时同步清理文件、索引和向量。

#### 正式实现验收

- 游客之间不能读取、检索或删除彼此资料。
- 公共资料只读。
- 深研确认后的资料只进入当前游客知识库。
- 阶段 7 的知识库导入服务消费阶段 6 已批准的研究结果，并负责唤醒 Index Agent；Research Agent 不直接写全局目录或调用 Index 子图。
- 行级引用继续保留文件名和行区间。
- 隔离设计能够扩展到未来 Skill 归属。

### 阶段 8：API Key 与模型设置

#### 目标

让游客通过浏览器安全地提供自己的模型配置，同时保证后端不持久化 Key。

#### 前端范围

- Provider、Base URL、模型名和 API Key 表单。
- 测试连接。
- 浏览器会话级保存。
- 缺少 Key 时阻止执行并引导配置。
- 清除 Key。
- 安全说明。
- 游客模式与开发人员模式的凭据来源提示；开发人员模式只显示只读状态，不展示 `.env` 内容。

#### 后端范围

- 请求头读取运行时凭据。
- LangGraph 主图与子图运行时注入。
- 日志和错误脱敏。
- Interrupt 恢复时重新接收 Key。
- 禁止 Key 进入持久化 state。
- 按服务端确认的身份选择凭据来源：游客必须提交自己的配置，开发人员与 Studio 才允许使用 `.env`。
- 禁止游客缺少 Key 时自动回退到 `.env`。

#### 正式实现验收

- 服务端文件、数据库、checkpoint 和日志中找不到 Key。
- 两个游客的运行时凭据不串用。
- 刷新和 Interrupt 恢复路径正确。
- 无 HTTPS 的生产配置拒绝敏感凭据或给出明确阻断。
- 生产默认禁用开发人员模式，游客无法借此调用服务端模型额度。

### 阶段 9：自动中断、恢复与集成收尾

#### 目标

完成跨会话切换、断线、刷新、失败和部署环境下的行为闭环。

#### 范围

- 切换会话前自动中断。
- 页面关闭或连接断开处理。
- 最近 checkpoint 自动恢复。
- 单长任务互斥。
- 重复提交与幂等保护。
- 错误边界和可操作的重试。
- 旧静态页面退役。
- 桌面端浏览器兼容性。
- 部署说明与安全检查清单。

#### 正式实现验收

- 不允许同一游客并发运行两个长任务。
- 刷新和重新进入能恢复到正确状态。
- 重复点击不会重复恢复 Interrupt 或写入知识库。
- 关键用户故事端到端通过。
- ruff、mypy `--strict` 和精简测试通过。

## 11. 测试策略

### 11.1 后端

- Thread 所有权与游客隔离测试。
- 统一事件顺序、去重和分页测试。
- Interrupt 归一化与幂等恢复测试。
- Main/Resume 交接契约测试。
- 知识库资源归属与强制过滤测试。
- API Key 不持久化和日志脱敏测试。
- 单长任务互斥测试。

### 11.2 前端

- 以少量关键组件测试覆盖消息方向、Agent 身份和交互卡片。
- 以状态机/数据层测试覆盖 SSE 解析、事件去重、恢复和会话切换。
- 不为纯视觉细节编写脆弱测试。
- 若测试环境连续无法运行，应按 `AGENTS.md` 及时与用户讨论是否保留该测试及其阻碍。

### 11.3 端到端用户故事

至少覆盖：

1. 游客创建多个会话并切换。
2. 普通问答与 RAG 引用。
3. 深研计划、详细进度、知识库确认。
4. Main → Resume 交接、逐条审批、保存退出、Main 恢复。
5. Resume 中途刷新并恢复。
6. 长任务切换会话时中断，再次进入时恢复。
7. 两个游客的 Thread 和知识库隔离。
8. API Key 缺失、错误、清除和恢复场景。

## 12. 每阶段固定协作流程

每个阶段都必须完整执行：

1. **边界陈述**：说明本阶段做什么、不做什么、会影响哪些现有行为。
2. **快速原型**：只写入 `prototypes/`，验证本阶段关键风险。
3. **协商**：展示原型结果、接口草案和交互细节，持续修改至双方无异议。
4. **批准**：用户明确说“开始”或“批准”后，才写正式代码。
5. **正式实现**：只实现本阶段所需内容，不为后续阶段提前占位。
6. **验证**：功能测试优先，并满足 ruff、mypy `--strict` 和精简测试。
7. **验收**：由用户检查真实交互与结果。
8. **Git 存档**：仅在用户验收后，并按用户指引提交或打 tag。

## 13. 计划评审重点

在批准总体计划前，需要重点确认：

1. 是否认可先做基础状态与事件层，再正式搭建 React 页面。
2. 是否认可把视觉完整的 Resume 工作区放到阶段 5，而不是第一阶段直接重写页面。
3. 是否认可知识库管理位于 Research 进度之后，以先稳定深研产物协议。
4. 是否认可 API Key 页面正式实现后置，但安全原型必须最先完成。
5. 是否需要调整九个阶段的粒度或优先顺序。
