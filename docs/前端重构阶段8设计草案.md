# 前端重构阶段 8 设计草案：API Key 与模型设置

> 实现状态：正式代码已完成，等待用户验收。

## 1. 目标与现状

目标是让游客使用浏览器会话内的 OpenAI-compatible 模型配置，同时保证 API Key 不进入后端持久化层；开发人员继续使用 `.env`，前端永远不读取或展示其值。

已经具备：

- 游客配置保存在 `sessionStorage`；
- 每次 chat、checkpoint、个人/公共知识索引请求通过 `X-IA-*` 请求头重新提交；
- 后端用请求级 `ContextVar` 注入 `ChatOpenAI`，不写 Agent State；
- 开发身份忽略浏览器模型请求头并使用 `.env`；
- 非本机 HTTP 页面拒绝接收游客 API Key；
- 产品事件拒绝敏感字段，任务失败只记录异常类型；
- 生产默认关闭开发人员登录。

本阶段补齐：测试连接、清除配置、Provider 预设、开发模式只读状态、安全说明、上游 HTTPS 校验、并发隔离和持久化泄漏回归。

## 2. 凭据生命周期

```text
用户输入 API Key
  ↓
React 组件内存
  ↓ 保存
浏览器 sessionStorage（仅当前标签页会话）
  ↓ 每次需要模型的请求
X-IA-API-Key / API-Format / Base-URL / Model 请求头
  ↓
FastAPI 校验 HTTPS、身份与字段
  ↓
RuntimeModelConfig ContextVar
  ↓
ChatOpenAI 构造
  ↓ 请求结束 finally reset
```

禁止进入：请求体、MainState、子图 State、ToolMessage、产品事件、SQLite、Markdown、Chroma 和日志。

`sessionStorage` 比长期 Cookie/localStorage 更符合第一版需求：关闭标签页后清除，且后端不持有用户 Key。它仍无法抵御同源 XSS，因此前端不得引入不可信脚本，Markdown 渲染继续执行 sanitize，并在页面明确说明这是“浏览器会话级保存”，不是硬件密钥库。

## 3. 设置界面

游客设置弹窗包含：

- Provider：`DeepSeek`、`OpenAI`、`自定义 OpenAI-compatible`；
- Base URL；
- Model；
- API Key 密码框；
- “测试连接”；
- “保存配置”；
- “清除配置”；
- 安全说明和当前保存状态。

Provider 只用于填写推荐 Base URL/模型，不进入后端协议；API 格式会作为稳定协议字段传递。第一版仅接受 `openai-chat-completions`，由后端统一使用 `ChatOpenAI`。

测试连接调用独立端点，不创建 Thread、不执行图、不写产品事件。后端使用请求级配置发送一个最小模型请求，前端只得到 `{ok, model}` 或脱敏后的稳定错误，不返回供应商原始异常正文。

开发人员打开设置时展示只读状态：

```text
凭据来源：服务端 .env
模型配置：由开发环境管理
API Key：不会发送到浏览器
```

不显示输入框，也不允许浏览器请求头覆盖 `.env`。

## 4. 传输安全

需要同时保护两段链路：

1. 浏览器 → InterviewAssistant：生产环境必须 HTTPS；`localhost/127.0.0.1/::1` 允许 HTTP 调试。
2. InterviewAssistant → 模型 Provider：Base URL 必须 HTTPS；只对本机 Provider 地址允许 HTTP。

部署在反向代理后时，以可信代理传入并由 ASGI server 解析后的 scheme 为准。生产环境必须设置 `IA_COOKIE_SECURE=true`，否则能力接口应显示安全配置异常，不能默默宣称安全。

## 5. Interrupt 与恢复

API Key 不在 checkpoint 中，因此：

- 普通消息每次携带配置；
- Interrupt 的批准/拒绝请求仍携带配置；
- `/v1/checkpoint` 自动恢复仍携带配置；
- 刷新后从当前标签页 `sessionStorage` 重新读取；
- 如果配置已被清除，前端先打开设置，不发送恢复请求。

这是刻意的安全边界：checkpoint 能恢复业务状态，但不能恢复秘密。

## 6. 并发隔离与脱敏

- 每个请求使用独立 ContextVar token；
- 并发请求结束后上下文必须恢复为 `None`；
- 任何日志调用不得传 `RuntimeModelConfig`、请求 headers 或供应商异常正文；
- API 错误只返回稳定错误码，如 `MODEL_CONNECTION_FAILED`；
- 测试使用唯一假 Key 扫描 checkpoint、Store、应用数据库、产品事件和捕获日志。

## 7. API 草案

```text
POST /v1/model-config/test
Headers: X-IA-API-Key, X-IA-API-Format, X-IA-Base-URL, X-IA-Model

200 { "ok": true, "model": "..." }
4xx/5xx { "error": { "code": "MODEL_CONNECTION_FAILED", ... } }
```

开发身份调用时只测试 `.env` 配置，忽略浏览器模型请求头。

## 8. 快速原型与验收

原型验证：

- 两个并发游客分别看到自己的 Key/模型；
- 请求退出后 ContextVar 清空；
- checkpoint/事件/日志模拟载荷不含假 Key；
- Interrupt 恢复请求若没有重新提交配置则被拒绝；
- 非本机 HTTP Provider URL 被拒绝。

正式验收：

- 测试连接成功和失败反馈清晰；
- 清除配置后立即阻止下一次图执行；
- 刷新、Interrupt 和 checkpoint 恢复正确；
- 开发模式不展示 `.env` 内容；
- 全量持久化文件和日志扫描找不到测试 Key；
- ruff、mypy strict、单元测试和前端构建通过。

## 9. 正式实现前需要确认

1. Provider 第一版只提供 DeepSeek、OpenAI、自定义三个选项，底层均走 OpenAI-compatible。
2. “测试连接”会产生一次极小的模型调用，可能产生少量供应商费用。
3. API Key 继续使用 `sessionStorage`，不提供跨标签页或关闭浏览器后的保存。
