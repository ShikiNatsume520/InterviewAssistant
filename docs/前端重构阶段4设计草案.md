# 前端重构阶段 4：多 Agent 交接契约设计草案

> 当前状态：阶段 4B 已完成正式实现，等待用户验收。

## 1. 阶段目标

在 Main Agent 与 Resume Agent 继续保持独立消息历史的前提下，通过显式、可校验的双向交接契约保持上下文连续，并让前端始终知道当前输入交给哪个 Agent。

## 2. 本阶段实现范围

### 2.1 Main → Resume

Main Agent 调用 Resume Agent 时只提交最小交接信息：

```text
ResumeTaskBrief
├─ resume_id         必填，实际源简历
└─ user_request      可为 None
```

约束：

- `user_request` 使用用户原话或忠实的简短概括，可自然包含已经明确的岗位、范围和约束。
- 不传 Main Agent 的完整消息历史。
- 不传整份简历；wrapper 校验归属后按 `resume_id` 读取只读源简历并初始化工作草稿。
- 任务细节不足时，由读取过简历的 Resume Agent针对内容继续询问用户。

### 2.2 Resume → Main

Resume Agent 退出时返回结构化结果：

```text
ResumeTaskResult
├─ source_resume_id
├─ output_resume_id  保存时为新 ID，放弃时为空
├─ outcome       saved | discarded
├─ summary       Resume Agent 已有的任务总结
└─ display_name  保存结果或源简历的显示名称
```

本阶段不新增“修改列表、edit ID、章节定位、Diff 展示”等阶段 5 字段。

### 2.3 会话活动模式

Thread 元数据增加：

```text
active_mode   chat | resume
active_agent  main | resume
```

- 普通对话默认为 `chat/main`。
- Resume 子图进入后为 `resume/resume`。
- Resume 保存或放弃退出后恢复为 `chat/main`。
- 刷新页面后，前端只读取 Thread 元数据决定接收者提示，不从消息文本猜测。
- LangGraph checkpoint 仍是执行状态和 Interrupt 恢复的唯一依据；活动模式只是产品路由与展示元数据。

### 2.4 前端交互

- `agent.transition` 继续作为模式分隔条，不清空历史。
- 输入框上方显示 `发送给 Main Agent` 或 `发送给 Resume Agent`。
- Resume 模式中，用户输入通过现有 pending Interrupt 恢复子图，不作为新的 Main Agent `HumanMessage`。
- Resume Agent 收到明显无关的问题时，说明当前处于简历编辑模式，并引导用户先保存或放弃退出；不私自转交 Main Agent。
- 保存和放弃退出只在 `hitl_standby` 中提供。计划确认和逐条修改审批期间必须先完成当前决策，不能同时退出。
- 简单修改允许直接进入逐条审批；复杂或多处修改必须先生成并确认计划。
- 放弃退出是终局操作，不能恢复该草稿，只能基于源简历重新开始一轮编辑。

## 3. 本阶段明确不做

- 不实现中间 Resume 工作区。
- 不实现文件选择、计划确认和逐条审批的 React 卡片。
- 不增加 edit ID、红绿 Diff 或章节定位字段。
- 不改变逐条 `grep_replace` 审批机制。
- 不实现 Research Agent 的结构化交接；本阶段只完成 Main ↔ Resume 闭环。
- 不合并 Main 与 Resume 的消息历史。

## 4. 后端局部重构点

- `src/agents/main/tools/resume_agent.py`：工具参数精简为 `resume_id + user_request?`，wrapper 返回结构化结果。
- `src/agents/main/prompts.py`：约束 Main Agent只负责入口级澄清，不为填满交接字段而过度询问。
- `src/agents/resume/state.py`：保存任务简报及退出结果所需的最小字段。
- `src/agents/resume/prompts.py`：让 Resume Agent读取简历后自行完成专业澄清，不足信息必须询问。
- `src/server/identity.py`：持久化 Thread 活动模式和活动 Agent。
- `src/server/app.py`：在 Agent 进入/退出时更新 Thread 元数据，并向前端返回字段。

## 5. 需要协商的决策

1. Resume 模式中出现无关问题时，是提示用户先退出，还是允许显式按钮“退出并转交 Main Agent”。草案推荐第一版只提示，不自动转交。
2. 已确认：`discarded` 只返回用户已放弃，不创建派生简历，也不向 Main Agent返回完整草稿。
3. 已确认：保存和放弃退出只在 `hitl_standby` 开放；计划确认与逐条审批中断只处理各自当前决策。
