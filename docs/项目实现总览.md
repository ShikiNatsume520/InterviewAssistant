## 1. 项目定位

基于 **LangGraph** 的本地多智能体 MVP，做三件事：

1. **Agent / LangGraph 领域知识问答**——本地知识库 RAG 检索 + 行级引用 + 知识缺口识别。
2. **简历优化**——人机协同（HITL）的常驻编辑会话，逐条 approve/reject/suggest。
3. **自主联网深研**——RAG 判定知识缺口后，经用户同意，联网搜集资料、整理入库、重建索引。

一句话：一个能体现 Agent Engineering 深度的本地系统，主图通过 LLM 原生 tool calling 调度多个子智能体，全程可中断、可恢复、可回放。

## 2. 技术栈

| 层 | 选型 |
|---|---|
| 编排框架 | LangGraph（StateGraph + 子图 + interrupt + checkpointer + Store + subgraphs 流式） |
| LLM | OpenAI 兼容端点（`langchain-openai` 的 `ChatOpenAI`，对接 DeepSeek / OpenAI / Qwen / 智谱等） |
| Embedding | SiliconFlow API `BAAI/bge-large-zh-v1.5`（1024 维，OpenAI 兼容，在线） |
| 向量库 | Chroma（cosine 空间，单 collection `knowledge_base`） |
| 持久化 | `AsyncSqliteSaver`（checkpointer）+ `SqliteStore`（长期记忆） |
| Web 后端 | FastAPI + sse-starlette（SSE 流式） |
| Web 前端 | 原生 HTML/JS（`static/index.html` 主页 + `static/resume.html` 简历页） |
| 深研工具链 | ddgs（DuckDuckGo 搜索）+ httpx + trafilatura（网页爬取与正文提取） |
| 工程 | `uv` 包管理、ruff + mypy `--strict`、LangGraph Studio 可视化调试、openspec 规范化重构 |

包管理一律用 `uv`（仓库根有 `uv.lock`），不混用 pip。

## 5. 核心数据流（一次知识问答）

1. 前端 `POST /v1/chat`（带 `thread_id` + `message`）。
2. server 无 pending interrupt → `astream({"messages":[HumanMessage], "user_id"}, config)`。
3. 主图 `chat_node`：从 Store 读长期记忆拼到 system prompt 尾部 → `bind_tools(ALL_TOOLS).invoke(messages)` → LLM 决策。
4. 若 LLM 调 `rag_agent(query, search_type)`：`route_after_chat` 查 `ROUTE_TABLE` 命中 → `Send("rag_agent", {"tool_call": tc})` → wrapper `await rag_graph.ainvoke(...)` → 双管道检索 → 返回 `ToolMessage`（带行号引用）+ `citations` → 回 `chat_node`。
5. 若检索结果为空 → RAG 判 `gap_topic` → `chat_node` 据 system prompt 先用自然语言问用户"要不要深研"，得同意后调 `research_agent`。
6. `chat_node` 最终无 tool_call → 文本流式 token 经 SSE `event:token`（`ns:"main"`）推前端 → 流末无 interrupt → `event:done`（含 last_message + citations）。
7. `route_after_chat` 无 tool_call → `Send("save_memory", ...)` → 提取事实写 Store → END。

**HITL 流程**：子图内 `interrupt()` → wrapper 透传 `GraphInterrupt` → 主图暂停 + checkpoint 存档 → SSE `event:interrupt`（payload 经 contracts schema 校验）→ 前端弹窗 → 用户操作 → 下次 `POST /v1/chat` 带 `resume_value` → server 发 `Command(resume=value)` → 主图重新进 wrapper → 子图靠继承的 checkpointer 从挂起点恢复。

**刷新恢复**：前端 `GET /v1/state` 解析最近 checkpoint（停在哪个图 / pending interrupt / messages 快照）→ 有待续跑则 `POST /v1/checkpoint`（`astream(None, config)` 从最近 checkpoint 续跑）。

## 6. 各模块详解

### 6.1 kernel 横切层（R0 抽取）

横切关注点收敛为唯一真相源，消除"持久化三套并存 / 模型名多处硬编码 / import 混用 src.client"等技术债。

- **[config.py](../src/kernel/config.py)**：`DEFAULT_MODEL` + 4 场景模型常量（`CHAT_MODEL`/`EXTRACTION_MODEL`/`RESUME_MODEL`/`RESEARCH_MODEL`）+ provider（`DEEPSEEK_API_KEY`/`DEEPSEEK_API_URL`），全 `os.getenv` 读取，默认 `deepseek-v4-flash`。选项 A（重启切换，不做 per-request 注入）。
- **[contracts.py](../src/kernel/contracts.py)**：8 个 Pydantic schema 固化 interrupt 契约（详见 §6.4/§6.5）。`server` 序列化、子图 `interrupt()` 构造、校验共用同一组类型，改协议有编译期保障。
- **[llm.py](../src/kernel/llm.py)**：`get_chat_model(model=None, tools=None)` 统一入口；`model=None` 读 `DEFAULT_MODEL`；含 `deepseek` 走 `ChatOpenAI(api_key=DEEPSEEK_API_KEY, base_url=DEEPSEEK_API_URL)`，否则走默认 OpenAI env；`tools` 非空则 `bind_tools`。
- **[embedder.py](../src/kernel/embedder.py)**：`SiliconFlowEmbeddingFunction`（OpenAI 兼容，env `SILICONFLOW_*`）+ `COLLECTION_NAME="knowledge_base"` 常量（rag/index 共享）+ `get_embed_fn()` 单例缓存。
- **[persistence.py](../src/kernel/persistence.py)**：`generate_checkpointer()`（async context manager，供 Studio）+ `get_store()`（sync，供主图）+ 路径常量 `CHECKPOINT_DB_PATH` / `STORE_DB_PATH`。
- **[paths.py](../src/kernel/paths.py)**：`PROJECT_ROOT` / `MARKDOWN_DIR` / `RESUMES_DIR` / `CHROMA_PATH` / `INDEX_MD_PATH` / `LOGS_DIR`。
- **[logging.py](../src/kernel/logging.py)**：`dlog(scope, node, msg, **extra)`——按 scope 缩进，stderr + 文件双写（`logs/debug_*.log`），`IA_DEBUG=1` 开关。无 `slog`（"双通道"指单函数内双 handler）。配套 `summarize_messages()`。

### 6.2 主图 main（[graph.py](../src/agents/main/graph.py)）

- **chat_node**：`bind_tools(ALL_TOOLS).invoke(messages)`，LLM 自主决策；每次从 Store 读长期记忆拼 system prompt 尾部。
- **route_after_chat**（[routing.py](../src/agents/main/routing.py)）：查 `ROUTE_TABLE`，统一返回 `list[Send]` 支持**并行 fan-out**——每个子图 tool_call 发一个 Send 到其 wrapper，一般工具发一个 Send 到 `tools_node`（带只含一般工具的 masked AIMessage 副本，避免 ToolNode 撞上子图工具的 `raise RuntimeError`），无 tool_call 发一个 Send 到 `save_memory`。
- **registry**（[registry.py](../src/agents/main/registry.py)）：`SubAgentMeta` + `REGISTRY` 显式清单（rag/resume/research）+ `ROUTE_TABLE`。新增子 agent = 一 wrapper 模块 + 清单一行，主图拓扑零改动。
- **可拔插布线**：`build_main_graph` 遍历 `REGISTRY` 做 `add_node`/`add_edge`/`path_map`/`ALL_TOOLS`。
- **模块级 `graph = build_main_graph(checkpointer=False)`**：让 `langgraph dev` 平台接管持久化。
- **MainState**（[state.py](../src/agents/main/state.py)）：`messages`（add_messages）+ `citations`（operator.add）+ `user_id` + `current_resume` + `research_output`。无子图 I/O 槽位——子图通信走 `ToolMessage`（消息即协议）。

### 6.3 RAG 子图（[rag/](../src/agents/rag/)）

两节点 `retrieve → aggregate`。

**双轨索引**（互补不同检索盲区）：
- 行级向量索引（Chroma）：片段级稠密召回，metadata 全程携带 `start_line`/`end_line`。
- LLM 增量维护的 `index.md`：主题级导航（关键词/摘要/文件维度），自主判断合并/新建。

**双管道互斥检索**（由 main agent 经 `search_type` 显式选路，而非融合重排）：
- `semantic`（[retrieval.py:299](../src/agents/rag/tools/retrieval.py)）：余弦向量召回 → 标题节扩展（按 `(file, heading)` 合并相邻/重叠行区间）→ `SCORE_LOW_THRESHOLD=0.55` 阈值过滤。
- `keyword`（[retrieval.py:171](../src/agents/rag/tools/retrieval.py)）：`index.md` 关键词匹配定位候选文件 → 定向 grep，无候选退化全目录 grep。score 为词覆盖率。

**gap 判定**（[retrieval.py:414](../src/agents/rag/tools/retrieval.py)）：`aggregate_results` 仅当 `raw_results` 为空时判 gap（回填 `gap_topic`）。原 `top_score/avg_score < 1.15` 分差比规则因短文本块分数分布压缩易误判**已废弃**，`_compute_confidence` 计算的 ratio 仅用于 dlog 日志。TODO 标注未来用 LLM 智能汇总替代硬阈值。

**行级引用全链路**：`RawResult`/`Citation` 含 `file_path`/`start_line`/`end_line`/`content`/`score`；主图 system prompt 要求 LLM 插入 `[x]` 角标 + 末尾 `## 参考资料` 块（每行=编号+文件名+行区间）。

### 6.4 Resume 子图（[resume/](../src/agents/resume/)）—— ⚠️ 当前为重构后范式

> **重要**：resume 子图已从早期的"section 级 CRUD 工具 + Command(update) + last_draft 快照"模式，**彻底重构为「后端驱动常驻编辑会话 + grep_replace 逐条 approve 小循环」**。旧的 `add_section`/`update_section`/`ToolRuntime`/`Command(update)`/`last_draft` 快照均已不存在。

**9 节点**（[graph.py:609-617](../src/agents/resume/graph.py)）：

```
START → select_resume(interrupt: 等前端回传 {resume_file, resume_shot})
      → init(入口哨兵)
      → chat_node  ★ 唯一 LLM 决策点（文本走流式 token，不存 state）
          ├─ grep_replace(一波多个) → edit_executor ⟷ approve_node  (逐条小循环)
          ├─ request_plan → plan_node → plan_confirm(interrupt)
          └─ 无 tool_call → hitl_standby(interrupt: 常驻待命)
                              ├─ new_request → chat_node
                              ├─ exit(save=True)  → persist(不写文件) → END
                              └─ exit(save=False) → END
```

**核心范式**：
- **流式 token（namespace 区分）+ 流后 aget_state 查 interrupt**：`chat_node` 文本回复由 `astream(stream_mode="messages", subgraphs=True)` 实时推前端（`ns=resume_agent`），**不存 state、不进 payload**；interrupt 信号是流终止后用 `aget_state` 查 `task.interrupts[].value` 得到。
- **后端不碰文件 IO**：`select_resume_node` 不扫不读文件（前端用 `<input type=file>` 选单个 .md，回传 `{resume_file, resume_shot}`）；`persist_node` 不写文件（最终 shot 经 `done` 回复返前端，前端负责写回本地）。
- **grep_replace 确定性工具**（[tools/edit.py](../src/agents/resume/tools/edit.py)）：LLM 从 prompt 里的 `resume_shot` 自己找出要改的片段作 `grep_target`，后端做 find→replace，**工具内无 LLM**。唯一性校验：不存在返错，多处命中返错并附行号帮 LLM 用更长片段重定位。
- **逐条 approve 小循环**：`chat_node` 一波可发多个 `grep_replace` tool_call，`edit_executor_node` 取一条判断 grep（只判断不替换），命中进 `approve_node` 显示 diff（`before`/`after`/`edits`，前端标红绿）请用户 approve/reject/suggest——approve 即替换 shot 取下一条，reject 转 hitl_standby，suggest 回 chat_node。`processed_edits`（tool_call_id 集合）跟踪已处理，逐条推进。新发一波是新 AIMessage（新 id），自动覆盖旧波未执行的。
- **常驻待命**：`hitl_standby_node` 三态路由——new_request（注入 HumanMessage）→ chat_node；exit(save=True) → persist → END；exit(save=False) → END。靠「是否注入 HumanMessage」+「save」区分，无额外 flag。

**interrupt 使用**（4 处）：`select_resume`（`ResumeSelectPayload`，仅带 intent）、`plan_confirm`（`PlanConfirmPayload`）、`approve_node`（`ResumeApprovePayload`，带 before/after/edits）、`hitl_standby`（`ResumeHitlPayload`，带 summary）。

**工具**：`grep_replace`（确定性编辑）+ `request_plan`（仅作路由信号，被路由拦截不进 ToolNode）。

### 6.5 Research 子图（[research/](../src/agents/research/)）

**8 节点**（[graph.py](../src/agents/research/graph.py)）：`outline → outline_confirm → connectivity_check → connectivity_interrupt → search → finalize → index_rebuild → abort`。

> 与早期"7 节点、connectivity_check 一个节点既累计又 interrupt（POST-INTERRUPT 模式）"不同，当前**拆成两节点**：`connectivity_check` 只写累计 + payload（PRE-INTERRUPT），`connectivity_interrupt` 只负责 `interrupt()` 挂起。

**流程**：
- `outline_node`：LLM 据 `gap_topic` 生成 3-5 互补检索词。
- `outline_confirm_node`：`interrupt(OutlineConfirmPayload)` 等用户审阅大纲（approve / suggest 重规划 / reject 终止）。
- `connectivity_check_node`：调 `connectivity_probe()` 判通断；不通时 PRE-INTERRUPT 写 `connect_attempts+1` + `_pending_interrupt` → 路由到 `connectivity_interrupt`。
- `connectivity_interrupt_node`：`interrupt(ConnectivityCheckPayload)` 挂起提示挂梯子；resume 后 `route_after_connectivity_interrupt` 再 probe 一次：通→search，不通且 `attempts>=3`→abort，不通且 `<3`→回 `connectivity_check`。
- `search_node`：遍历 outline 逐词 `ddgs` 搜索 top-3 → `httpx`(强制 HTTP/1.1，TUN 环境更稳)+`trafilatura` 爬取正文 → LLM 提炼笔记。单 URL 失败重试 1 次，最终失败静默跳过。
- `finalize_node`：LLM 整理笔记成结构化 Markdown → 写入 `data/markdown/deep_research_<slug>.md`。
- `index_rebuild_node`：**跨子图** `await index_graph.ainvoke({"target_files":[new_file]})` 重建索引。
- `abort_node`：连通性失败设 `approval_status="aborted"`，用户拒大纲设 `rejected`。

**触发策略**（主图 system prompt）：RAG 判定 `gap_topic` 后，`chat_node` 先用自然语言问用户"要不要深研"，得**明确同意**才调 `research_agent`——避免高开销操作（单次可能 10+ 次 LLM + 爬 15 页）擅自触发。

**确定性循环 + 失败容错**：outline 3-5 词 × 每词 top-3 URL，总爬取上限约 15 页，耗时与搜索量可预期；每个 URL 失败静默跳过，`finalize` 即使无有效笔记也写最小记录文件以便索引重建可追溯。

### 6.6 Index Agent（[index/](../src/agents/index/)）—— 后台 agent

**5 节点线性**：`scan → chunk → embed → llm_index → write_index`。

**定位**：不进主图、不进 registry、不被对话节点调用；主图只只读其产出（`index.md` / Chroma）。被 research 子图完成后 `ainvoke` 复用入口，CLI 也可唤醒（`python -m cli index <files>`）。这是"索引重建（写路径，慢、可重试）"与"问答检索（读路径，需快）"的读写分离。

**实现要点**：
- **行级切片**（[tools/chunking.py](../src/agents/index/tools/chunking.py)）：按标题结构切，metadata 严格保留 1-based 闭区间 `start_line`/`end_line`；代码围栏（```/~~~）内 `#` 不当标题（`FENCE_RE` + `in_fence` 翻转）；超长块字符级二次切分（`MAX_CHARS=500` + `OVERLAP=50`，行号经 offset→line 回填，防死循环保险）。
- **Chroma 灌入**（[tools/vectorstore.py](../src/agents/index/tools/vectorstore.py)）：单 collection `knowledge_base`，cosine 空间，按 `chunk_id = f"{file}:{start}:{end}"` upsert 去重覆盖。
- **LLM 维护 index.md**（[tools/llm_index.py](../src/agents/index/tools/llm_index.py)）：LLM 看"现有索引 + 新文件 chunks"自主判断合并已有项/新建条目/无关行原样保留（LLM-as-judge 在数据管道落地）；**引用格式由后端确定性代码拼接**，LLM 不碰格式不碰行号。
- **结构化输出三级降级**：针对 thinking 模型不支持强制 `tool_choice=required`（`with_structured_output` 返回 400），用 `bind_tools(auto)` → 取 `tool_calls` 校验 → 未调用则兜底从文本抽 JSON 的三级策略。核心思想：凡是能用确定性代码兜住的，就不把正确性押在 LLM 上。

### 6.7 Server（[server/app.py](../src/server/app.py)）

FastAPI 端到端服务，应用生命周期持有 `AsyncSqliteSaver` + 编译后的主图单例。

| 端点 | 作用 |
|---|---|
| `POST /v1/chat` | 流式对话：有 pending interrupt→`Command(resume=value)`，否则新 `HumanMessage` 启动一轮 |
| `POST /v1/checkpoint` | 从最近 checkpoint 续跑（`astream(None, config)`），用于刷新恢复 / 卡在节点间自动续跑 |
| `GET /v1/state` | 解析最近 checkpoint，返回前端 init 所需路由+渲染数据（停在哪个图 / pending interrupt / 主图+子图 messages 快照 / current_resume / citations） |
| `GET /v1/thread` | 返回当前会话 thread_id（进程内存，重启丢失） |
| `GET /health` | 健康检查 |
| `GET /` | 主页前端 `index.html` |
| `GET /resume` | 简历专用前端 `resume.html` |

**SSE 事件**（`stream_mode="messages"` + `subgraphs=True`，token 带 `ns` 区分主图 main / 子图 resume_agent）：
- `token`：`{ns, text}`，捕获主图 + 嵌套子图 LLM token，按 namespace 归一化。
- `interrupt`：图挂起，data 为经 `_PHASE_TO_SCHEMA`（contracts schema）校验后的 interrupt payload。
- `done`：本轮结束无 interrupt，data 含 `last_message` + `current_resume` + `citations`。

**interrupt 契约固化**：`_PHASE_TO_SCHEMA` 映射 6 个 phase→contracts schema，`_interrupt_payload` 用 schema 校验后序列化，确保字段形状。

**子图 state 摘要**：`_extract_subgraph_state` 从主图 `state.tasks[].state` 挖 resume 子图 state（`resume_shot`/`resume_file`/`plan`/`messages`），供 `/resume` 前端恢复左右栏。

## 7. 关键技术设计

### 7.1 子图即工具：用 LLM 原生 tool calling 替代自定义路由协议
子图用 `@tool` 包装为标准 Tool，与普通工具统一 `bind_tools`；`route_after_chat` 只做机械拦截分流（子图走 wrapper `ainvoke`、普通工具走 `ToolNode`）。子图工具函数体显式 `raise RuntimeError` 强制走 wrapper，避免 ToolNode 自动执行与子图状态映射冲突，同时让子图能访问完整图状态。把"该调哪个子图"的语义判断交给 LLM 而非路由代码。

### 7.2 Studio 子图发现硬约束（深度调试能力）
Studio 的 `find_subgraph_pregel` 靠静态分析节点函数 AST 发现子图。wrapper **必须**模块顶层 `from <agent>.graph import graph as X` + 函数体裸名 `await X.ainvoke(...)`，才能被 Studio 展开子图内部节点。惰性 getter / 体内 import / 体内编译都展不开。该约束由 `prototypes/phase7_registry_studio_probe.py` 实证钉死（6/6 PASS），R1 重构据此修复 research 子图"Studio 黑盒"潜伏 bug。`REGISTRY` 只作 build-time 布线清单，`node` 是静态 wrapper 函数引用（非工厂产物），`REGISTRY` 绝不出现在节点函数体内。

### 7.3 HITL 跨主图-子图 interrupt：GraphInterrupt 透传 + checkpoint 恢复
子图 `interrupt()` → wrapper 捕获 `GraphInterrupt` 并透传（`except GraphInterrupt: raise`）→ 主图 Pregel 捕获并暂停线程 → checkpoint 持久化 → 下一轮 `Command(resume=value)` 经主图重新进入 wrapper → 子图靠继承的父图 checkpointer 从挂起点恢复继续（而非重跑）。interrupt 子图的"长期驻留"语义完全靠 checkpoint 持久化，不需要显式状态机——复用 LangGraph 原生机制不引入新协议。

### 7.4 子图 checkpointer 链式继承 + 局部异步化
子图非无状态纯计算单元——wrapper 调用模块级预编译子图实例（编译时不传 checkpointer），运行时自动继承父图 checkpointer，子图内部每一步执行状态均在 SQLite 有记录。选异步 `ainvoke` 是因 platform 的 `_CustomCheckpointerAdapter` 只实现了异步接口——运行时接口检测驱动架构决策，让调用方适配接口形态而非让 checkpointer 补全套同步方法，`async def` 节点在同步主图中由 LangGraph 自动调度，局部异步化不污染其他节点。

### 7.5 并行 fan-out + masked AIMessage
`route_after_chat` 返回 `list[Send]` 支持一轮多个 tool_call 并行 fan-out。混合场景（子图工具 + 一般工具）时，给 `tools_node` 发一个只含一般工具 tool_call 的 masked AIMessage 副本，避免 ToolNode 撞上子图工具的 `raise RuntimeError`；主图原始 AIMessage 不动，故所有 ToolMessage 都能按原始 tool_call_id 匹配回主图 AIMessage。

### 7.6 后端驱动常驻编辑会话（resume 重构核心）
从"CRUD 工具 + 命令式写回 + 单步快照回退"重构为"流式 token + 流后查 interrupt + 逐条 approve 小循环"。后端不碰文件 IO（前端选文件、前端写回），chat_node 文本不存 state（流式 token 实时推前端）。逐条 approve 用 `processed_edits`（tool_call_id 集合）跟踪已处理，串行推进；新发一波是新 AIMessage 自动覆盖旧波未执行的。常驻待命靠「是否注入 HumanMessage」+「save」三态路由，无额外 flag。

### 7.7 双轨索引 + 读写分离
Chroma 行级向量索引（片段级稠密召回）+ LLM 维护的 `index.md` 语义索引（主题级导航）互补不同检索盲区。Index Agent 作为后台 agent 与对话主图彻底解耦——索引重建（写路径）与问答检索（读路径）分离，避免把数据维护这种副作用塞进实时对话回路。

### 7.8 结构化输出三级降级
针对 thinking 模型无法强制 `tool_choice` 的限制，`bind_tools(auto)` → 取 `tool_calls` 校验 → 未调用则兜底从文本抽 JSON 的三级策略，保证结构化输出在异构模型后端下可用——把正确性押在确定性代码而非 LLM。

### 7.9 横切关注点收敛（R0–R3 重构）
抽取 `kernel/` 作为横切关注点唯一真相源，引入可拔插 registry，模型名配置化，interrupt 契约 Pydantic 化，物理目录重排。消除 6 类技术债：持久化三套并存→统一、模型名 5+ 处硬编码→config 化、加子 agent 改 4 处→registry 一行、research Studio 展不开→修复、子图互依（rag→index 内部 embedder）→上提 kernel、import 混用 `src.client`→统一裸包名。全程 ruff + mypy `--strict` + Studio 子图发现不退化 + 端到端跑通。

## 10. 已知技术债

1. **server 与 Studio checkpoint 路径不一致**：[server/app.py:61](../src/server/app.py) 用相对路径 `"sqlite_checkpoints.db"`，未用 kernel 的 `CHECKPOINT_DB_PATH`（`data/state/checkpoints.sqlite`）。R0"Studio 与 server 共用路径"目标在 server 侧未完全收敛，两者实际不同库。简历优化流程可用，但 Studio 与 server 的 checkpoint 不互通。
2. **research 跨子图直调 index_agent**：[research/graph.py](../src/agents/research/graph.py) 的 `index_rebuild_node` 直接 `ainvoke` index_agent 图（跨子图调用），未走 CLAUDE.md 约定的"导入接口/命令"。属已知技术债，待重构改走导入接口。
3. **`SuggestDecision` 契约未实际使用**：[contracts.py:95](../src/kernel/contracts.py) 定义了 `SuggestDecision`，但 src 内无任何 import——suggest 场景前端发裸 dict `{decision:"suggest", suggestion:...}`，server/子图按通用 dict 解析，未走 Pydantic 校验。
4. **resume.html 死代码**：`onDirSelected` 引用 `$("modal-files")`（HTML 无此元素），是 webkitdirectory 多文件选择时代遗留，当前走单文件 `readAndSelect` 路径。
5. **简历版本未持久化到 Store**：设计文档原提"按 user_id 版本栈"未实现，resume 草稿维护在 `ResumeState`（内存态 + checkpointer 持久化），不写 Store。
6. **gap 判定简化**：原分差比 gap 规则废弃，现为"空结果判 gap"；retrieval.py 有 TODO 标注未来用 LLM 智能汇总节点替代纯 score 阈值。
7. **`/v1/thread` 单会话**：thread_id 存进程内存（重启丢失），多会话预留后续扩展。
8. **gap 时全目录 grep 范围**：knowledge_base 仅少量文件时无 I/O 延迟问题；文件量增大后 keyword 管道无候选时的全目录 grep 可能成为瓶颈（设计文档 §7.1 的开放性提问，当前未做"向量命中后定向 grep"优化）。
